# セットアップ

前提条件と、マーケットプレイスからユーザースコープで入れて、設定ファイルを用意する手順

## 前提条件

| 項目 | 内容 |
| --- | --- |
| OS | Linux（WSL2 を含む） |
| Claude Code | CLI のバージョン 2.1.310 以上 |

動作を確認しているのは上の OS とバージョンだけで、新しいバージョンでの動作は保証しない。

## 手順

<!-- steps -->

1. マーケットプレイスを登録する。

   ```bash
   claude plugin marketplace add shuhei1101/alias-inject
   ```

2. ユーザースコープでプラグインを入れる。

   ```bash
   claude plugin install alias-inject@alias-inject --scope user
   ```

3. プラグインの一覧で、入ったことを確認する。

   ```bash
   claude plugin list
   ```

   `alias-inject@alias-inject` が `Scope: user`・`Status: enabled` で出れば完了する。

<!-- /steps -->

## 設定ファイルを用意する

プラグインを入れただけでは、何も追加しない。
参照するリポジトリの `project-index.yaml` や照合する YAML を指定した設定ファイルを用意する。

Claude Code で `/alias-inject:global-setup` を実行すると、参照するリポジトリの `project-index.yaml` と用語集の YAML を聞いて設定ファイルを作り、引用の文脈が追加されることを確認する。
旧構造の設定ファイルがあるときは、新しい構造へ移す。

### 手で用意する

<!-- steps -->

1. 設定ファイルを配置するフォルダを作り、リポジトリの `settings.sample.yaml` をコピーする。

   ```bash
   mkdir -p ~/.config/alias-inject
   curl -fsSL https://raw.githubusercontent.com/shuhei1101/alias-inject/develop/settings.sample.yaml -o ~/.config/alias-inject/settings.yaml
   ```

2. コピーした `~/.config/alias-inject/settings.yaml` を編集し、`repositories` の `config` に参照するリポジトリの `project-index.yaml` のパスを指定する。
   端末だけのエイリアスは `aliases` に行として記載し、`paths` に照合する YAML のパス、`alias_type` に引用の種類を指定する。
   項目は [設定ファイル](./設定ファイル.md) を参照する。
   旧い `type`・`fields` の構造や `metadata.alias_type` の構造の設定を使用していたときは、[設定の移し替え](./設定の移し替え.md) で新しい構造へ移す。

3. 設定ファイルを既定のパス `${XDG_CONFIG_HOME:-~/.config}/alias-inject/settings.yaml` と違う場所に配置したときは、`~/.claude/settings.json` の `env` に `ALIAS_INJECT_CONFIG` を追加し、設定ファイルのパスを指定する。

   ```json
   {
     "env": {
       "ALIAS_INJECT_CONFIG": "~/notes/alias-inject.yaml"
     }
   }
   ```

   シェルの環境変数の `ALIAS_INJECT_CONFIG` でも指定できる。
   両方あるときは、`settings.json` の値を使用する。

4. Claude Code で、`aliases` の行の `paths` に挙げた YAML にある用語（`name` の値）を含む文を入力し、モデルの回答にその用語の説明が反映されることを確認する。

   設定ファイルや `project-index.yaml`、YAML を読み込めないときは、入力の送信は止まらず、読み込めなかったパスと理由が Claude Code の debug log に出る。

<!-- /steps -->

仕組みは [引用の文脈](./コアコンセプト-引用の文脈.md) を参照する。
