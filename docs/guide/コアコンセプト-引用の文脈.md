# 引用の文脈

入力の単語を YAML と照合し、モデルにだけ文脈を追加する仕組み

## 何が起きるか

入力を送信するたびに、入力の文に含まれる単語を、参照するリポジトリの `project-index.yaml` の `documents` の行と設定ファイルの `aliases` の行が指す YAML の用語・エイリアスと照合する。
該当した単語の説明（意味・文書の ID・コマンド・URL など）を引用の文脈としてまとめ、モデルにだけ追加する。
入力の文は変えずにそのまま返却する。

ツールの結果（Bash・Read・MCP のツールなど）の本文も、同じ設定と単語で照合し、該当した単語の引用の文脈をツールの結果の後ろに追加する。
本文は変えない。
ツールの結果は `origins` で絞らない。

次の入力は照合しない。

- スラッシュコマンドの行
- 設定の `origins` に無い出所の入力
- 設定ファイルが無い・読み込めないとき、`enabled` が `false` のとき

次のツールの結果は照合しない。

- 設定の `exclude_tools` に名前が完全に一致するツールの結果
- エラーの結果・他のフックが拒んだ呼び出し・本文の無い結果

照合で例外が起きても、ツールの結果は止めずに返却する。

設定ファイルや `project-index.yaml`、YAML を読み込めないときも、入力の送信は止めない。
読み込めなかったパスと理由は、Claude Code の debug log に出る。
読み込めない `project-index.yaml` は、そのリポジトリの定義だけを照合から除外する。
`documents` の行や `aliases` の要素がスキーマに合わないときも、その行だけを除外する。
`documents` の行が `alias_type` を持たず `metadata.alias_type` を持つ旧構造のときも、その行だけを除外し、移し替えが要る理由を debug log に出す。
必須のキーの値が空の文書と、照合条件が誤っている文書も、その文書だけを除外する。

## 照合

照合するのは、行の `metadata` が指す列の `name` と `aliases` の値（用語とエイリアス）だけ。
`aliases` の値が並びなら、要素ごとに照合する。
`name` が空の文書は、ファイル名（拡張子を除く）を使用する。`records` を指定した行の要素は、行の `body_file` が指す列の値のファイル名（拡張子を除く）、それも空なら `id` を使用する。

照合の前に、入力と単語の両方を次のようにそろえる。

- NFKC で正規化する
- 英字を小文字にする
- 前後の空白を除く

そろえた単語が、そろえた入力の部分文字列に含まれれば該当する。
正規表現は使用しない。
`exclude` に挙げた単語は照合しない。

1 つの項目の複数の単語（用語とエイリアス）がヒットしても、その項目は 1 回だけ追加する。
`global` と該当した `projects` の `aliases` の行と、参照する全てのリポジトリの `documents` の行を照合するので、別の行にある同じ単語は、どちらも追加する。

ツールの結果では、参照している文書そのものの単語を追加しない。

| ツール | 除外する単語 |
| --- | --- |
| Read | 単語の指す文書のパスが、参照したファイルのパス（`file_path`）と一致する単語 |
| MCP のツール（`mcp__` で始まる名前） | 文書の `id` が、ツールの引数の文字列の値（入れ子の値を含む）と一致する単語 |

単語の指す文書のパスは、`body_file` を記載した行では `body_file` の列の値（単語を取り出した YAML のフォルダからの相対パス）、それ以外の行では単語を取り出した YAML になる。

## 照合条件

文書の `inject_when` に照合条件を記載すると、`name`・`aliases` がヒットしても、照合した本文（入力の文か、ツールの結果の本文）が照合条件に該当しない文書は追加しない。
照合条件を持たない文書は、`name`・`aliases` が該当すれば追加する。
照合条件に該当せず追加しなかった単語は記録に入れないので、次に出た入力で追加の対象になる。

次の文書は、本文が `React` か `tsx` を含み、`Python` を含まないときだけ追加する。

```yaml
id: react-core-folder-structure
name: フォルダ構成
description: React のフォルダ構成の決まり
inject_when:
  and:
    - field: text
      op: contains
      values: [React, tsx]
    - field: text
      op: not_contains
      values: [Python]
```

照合条件の構造は [エイリアスのスキーマ](./エイリアスのスキーマ.md#照合条件) を参照する。

## 作業場所の絞り

行の `scope.cwd` に作業場所の glob を記載すると、セッションを起動したプロジェクトの直下がどれかの glob に該当する会話でだけ、その行の単語を照合する。
他の作業場所の会話では、その行の YAML を読み込まず、単語が入力やツールの結果に出ても追加しない。
`scope` を記載しない行は、全ての作業場所で照合する。

次の行は、話し合いのフォルダと aituber のリポジトリ（worktree を含む）の会話でだけ用語を追加する。

```yaml
id: talk-terms
paths: [~/repo/tmp/talk/terms.yaml]
alias_type: term
records: terms
scope:
  cwd: [~/repo/tmp/talk/**, ~/repo/aituber/**]
```

glob の該当の判定は [設定ファイル](./設定ファイル.md#作業場所の絞り) を参照する。

## 1 セッション 1 回

追加した項目は、セッション ID に紐づけて記録する。
記録は入力とツールの結果で共有するので、どちらかで一度追加した項目は、もう一方でも追加しない。
サブエージェントのツールの結果は、セッション ID とサブエージェントの ID の組で別に記録する。
サブエージェントで追加した項目は、メインの会話では追加済みにならない。
記録の単位は、定義の出所（`project-index.yaml` か設定ファイルの絶対パス）と行の `id` と文書の `id` の組なので、同じ項目をエイリアスで入力しても二度目は追加しない。
別のリポジトリが同じ行の `id` と文書の `id` を使用しても、それぞれを追加する。

記録は次のときに削除する。
削除した後に同じ単語を入力すると、文脈をもう一度追加する。

| きっかけ | 削除するか |
| --- | --- |
| 会話の圧縮（手動・自動・プラグインによる圧縮） | 削除する |
| `/clear` | 削除する |
| `claude --resume` で戻ったセッション | 削除しない。追加済みの文脈が会話に残っているため |
| サブエージェントの圧縮 | そのサブエージェントの記録だけを削除する |
| 圧縮の事前の計算 | 削除しない |

## 追加する量の上限

1 回に追加する単語は `max_items` 単語、文脈全体は `max_chars` 文字までで、既定は単語 20 個と 4,000 文字。
入力に最初に出た位置の早い単語から順に選び、同じ位置なら長い単語を先に選ぶ。
ツールの結果では、本文に出た回数の多い単語から順に選ぶ。
同じ回数なら、最初に出た位置の早い単語、同じ位置なら長い単語を先に選ぶ。
`max_chars` を超える単語は飛ばして、後ろの単語で収まるものを続けて選ぶ。
選ばれなかった単語は、その回に追加せず記録にも入れないので、次に出た入力で追加の対象になる。

## 引用の種類

行の `alias_type` が、追加する列を決める。
列の値は、行の `metadata` が列名で指す文書の列から取り、`metadata` に記載しないキーは同じ名前の列から取る。入れ子の列は `meta.summary` のように `.` でつなぐ。

| alias_type | 追加する列 |
| --- | --- |
| `term` | 単語・`id`・`description`・`related`（関連する文書の ID と名前） |
| `doc` | 単語・`id`・`description` |
| `command` | 単語・`id`・`command`・`cwd`・`description` |
| `url` | 単語・`id`・`url`・`description` |
| `skill` | 単語・`id`・`skill`・`description` |
| `tool` | 単語・`id`・`tool`・`description` |
| `path` | 単語・`id`・`path`・`description` |
| `env` | 単語・`id`・`url`・`port`・`description` |
| `avoid` | 単語・`id`・`replacement` |

`term` の文書の `avoid` に記載したやめた言い方が本文に出たときは、やめた言い方を単語、用語の `id` を `id`、用語の単語を `replacement` にして、`avoid` と同じ `使用しない単語` のセクションに並べる。

## 文脈の書式

文脈は `heading` の見出しの下に、`alias_type` ごとのセクションと、単語ごとの箇条書きで並べる。
セクションの見出しは `alias_type` ごとに固定で、`term` が `用語`、`doc` が `文書`、`command` が `コマンド`、`url` が `URL`、`skill` が `スキル`、`tool` が `ツール`、`path` が `パス`、`env` が `環境`、`avoid` が `使用しない単語`。
並びはこの順で、同じ `alias_type` の単語は、リポジトリや行が違っても 1 つのセクションにまとめる。
単語は `name` の値。
箇条書きの子には、`alias_type` ごとの列のうち値のあるものだけを並べる。

```markdown
# この発言に出る用語

## 用語

- 単一ユースケース（id: term-single-usecase）
  - description: 1 つの操作を始めから終わりまで記載するシナリオの単位
  - related: tpl-scenario（シナリオのテンプレート）

## コマンド

- セットアップ（id: cmd-setup）
  - command: `uv sync`
  - cwd: /mnt/c/Users/shuhe/repo/ai-monitor
  - description: 依存を入れる
```

設定ファイルの項目は、[設定ファイル](./設定ファイル.md) を参照する。
