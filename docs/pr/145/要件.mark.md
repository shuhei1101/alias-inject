# 要件

## 要望

[project-index.yaml](https://github.com/shuhei1101/alias-inject/blob/cf6f1d1/project-index.yaml) の `nav` で、dev-docs の画面のサイドバーのグループのうち入れ子にしたほうが探しやすいグループを入れ子にする。
決まりは規約『開発ドキュメントのナビゲーション』（knowledge の `dev-docs-navigation`）と、判定フローチャート『サイドバーのグループの分け方』（knowledge の `flowchart-sidebar-group-split`）に従う。

<!-- table: {"kind": "data"} -->

| 分類 | 終了の条件 |
| --- | --- |
| 入れ子の対象 | タブ「設計書」の各グループ（シナリオ・インターフェース定義・モジュール構成・外部ライブラリ）に判定フローチャート『サイドバーのグループの分け方』を当て、分かれると判定したグループだけを入れ子にする。分けなかったグループは判定の結果を記載する |
| 入れ子の階層 | 入れ子は 2 階層まで。上の階層は利用者の作業か機能の単位にする |
| グループの中の並び | 手順の順か重要さの順にし、名前の順にしない |
| nav に無い設計書 | 今の `nav` に並んでいない [IF-7](https://github.com/shuhei1101/alias-inject/blob/cf6f1d1/docs/interface/IF-7.yaml)・[SC-8](https://github.com/shuhei1101/alias-inject/blob/cf6f1d1/docs/scenario/SC-8.yaml) を、該当するグループに並べる |
| 画面の確認 | 修正した設定を dev-docs で開き、タブ「設計書」のサイドバーの入れ子のグループをスクリーンショットで確認し、reviewer の確認を受ける |

<!-- /table -->

## グループの判定

タブ「設計書」の各グループに、判定フローチャート『サイドバーのグループの分け方』を当てた結果。
並びを手順の順にするため、`auto.group_by` でなく `page` を並べて記載した。

<!-- table: {"kind": "data"} -->

| グループ | 判定 | 結果 |
| --- | --- | --- |
| シナリオ | Q1: YES。主題のタグ `topic:引用の文脈` を SC-1・SC-3・SC-2・SC-8 が持つ。ほかは 1 件ずつ | 単一ユースケースの SC-3・SC-2・SC-8 を「引用の文脈の追加」にまとめた。複合ユースケースの SC-1 はセッション全体の流れで、先頭に残した |
| インターフェース定義 | Q1: YES。`topic:引用の文脈`（IF-3・IF-2・IF-7）と `topic:記録`（IF-4・IF-1）で分かれる | 「引用の文脈の追加」「記録の消去」にまとめた。1 件ずつの IF-5・IF-6 はグループにしない |
| モジュール構成 | Q1: YES。主題のタグ `topic:スキーマ` を MOD-3・MOD-13・MOD-4 が持ち、全てのグループが 1 件ずつにはならない。ただし r1 のとおり主題のタグの値で分けると、ほかは 1 件ずつのグループが十数個並び、`flowchart-sidebar-group-split` の「意味のまとまりで見やすくなるように分ける」に合わない | 主題のタグの値を処理の流れの機能の単位にまとめ直し、`page` を並べて順を指定した（`dev-docs-navigation` の sidebar-02）。エントリポイントとイベント: `topic:エントリポイント`・`topic:イベント`。設定の読み込み: `topic:設定ファイル`・`topic:ファイル`・`topic:リポジトリ`。エイリアスの読み込み: `topic:エイリアス`・`topic:スキーマ`・`topic:単語`。照合: `topic:照合`・`topic:条件`・`topic:ツール`。文脈の組み立て: `topic:引用の文脈`・`topic:変数参照`。記録: `topic:記録`・`topic:契約` |
| 外部ライブラリ | Q1〜Q3: NO（主題のタグは 1 件ずつ・機能の項目なし・フォルダは 1 つ）。Q4: NO（全ての文書が主題のタグを持つ） | 分けずに並べた |

## テスト結果

コードを変えないため、関係する単体テストは無い。
結合テストの実行範囲は `judge_integration_scope`（TL-2）で全ての変更ファイルが R7 になった。
プラグインは参照する `project-index.yaml` の `documents` の行だけを読み、結合テストはフィクスチャの `project-index.yaml` を使用するため、`nav` の変更を参照する結合テストは無く、実行しない。
