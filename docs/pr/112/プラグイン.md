## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| ランナーでの初回の実行 | 作業ブランチで TL-1・TL-2 の `run_runner` を 1 回回し、出たログと実行の step ごとの所要時間（`gh run view --json jobs`）を記録する | 同じ commit を手元の `run_all` でも 1 回回す |
| skip の件数の比較 | ランナーと手元の `test.log` の集計の pass・skip・fail を並べる | 違う場合は skip したテストの名前から理由を特定する |
| ジョブのタイムアウト | ランナーの実測の全ての step の所要時間の合計の 10 倍を分に切り上げ、IF-6 と test.yml の両方に書く。`decided_by` は外し、`notes` に実測の値と導き方を書く | 判定フローチャート『タイムアウトの決め方』の ※5 |
| step のタイムアウト | ランナーの実測の 10 倍が 1 分を超えた step だけ、同じ導き方で導き直す | 内側は外側（ジョブ）より短くする |
| LIB-4 の動作確認 | 初回の実行で観測できた Action・キーの `verification_state` と `verification` を記録する。観測できない分岐（`if: always()` が失敗の後に動くこと・`timeout-minutes` で止まること・`if-no-files-found: warn`）は観測していない旨を残す | 異常系のフローの確認は #111 |
| ARCH-1 | 初回の実行が成功したら、外部システム GitHub Actions の `status` を `implemented` にする | - |
