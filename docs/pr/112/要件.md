# 要件

## 要望

develop へ入った workflow `.github/workflows/test.yml` を、単体（TL-1）・結合（TL-2）の `run_runner` でランナーで初めて回し、結果からタイムアウトと動作確認を記録する。

- 終わりの条件
  - `run_runner` でランナーの全件実行を回し、実行の結論が `success`、`test.log` の集計が `0 fail` になっている（IF-6 の正常系のフロー）
  - 同じ commit を手元の `run_all` でも回し、ランナーと手元の pass・skip の件数を並べて記録している。件数が違う場合は、違う理由を特定して記録している
  - IF-6 のジョブのタイムアウトを、ランナーの実測の step の所要時間の合計の 10 倍（分に切り上げ）から導き直し、`.github/workflows/test.yml` の `timeout-minutes` も同じ値にしている（判定フローチャート『タイムアウトの決め方』の ※5）
  - step「Claude Code を入れる」「テストの全件を回す」のタイムアウト（手元の実測の 10 倍から決めた 1 分）を、ランナーの実測の 10 倍が超えていないかを確かめ、超えていれば同じ導き方で導き直している
  - LIB-4 の `verification` と、使用する Action・workflow のキーの `verification_state` を、初回の実行で観測できた範囲で記録している
  - アーキテクチャ図 ARCH-1 の外部システム GitHub Actions の `status`（`planned`）を、初回の実行の結果に合わせている
  - ランナーの実行のログを PR ドキュメントの `テスト結果/` に置いている

プラグインの利用者の操作と振る舞いは変えないため、影響するユースケースは無い。
