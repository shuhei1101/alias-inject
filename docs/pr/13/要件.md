# 要件

## 要望

用語・文書のエイリアス・コマンド・URL を「どの YAML のどの列から取るか」を定義する共通の構造 `aliases[]` のスキーマを `schemas/aliases.schema.yaml` に置き、SSOT にする。
mdmark・dev-docs はこのスキーマだけを取り込み、alias-inject のコードには依存しない。
スキーマを変えるときは alias-inject に Issue を立てて変える。

### スキーマ

- 書式は JSON Schema（2020-12）を YAML で書いた `.schema.yaml`
- ルートは `aliases[]` の並びで、要素の定義を `$defs` に置く。取り込む側は自分の設定の `aliases` のキーからルートを `$ref` で指す
- 要素のキーは次のとおり。表に無いキーは許さない

  | キー | 型 | 必須 | 中身 |
  | --- | --- | --- | --- |
  | `id` | string | 必須 | 要素の主キー |
  | `enabled` | boolean | - | `false` のとき使わない。既定は `true` |
  | `type` | `term` / `doc` / `command` / `url` | 必須 | 引用の種類 |
  | `paths` | string の並び（1 件以上） | 必須 | 読む YAML のパスか glob。ファイルと glob を混ぜてよい |
  | `fields` | object | 必須 | 列の対応。キーは下の表、値は元の YAML の列の名前 |

- `fields` の `match` は本文・入力と照合する語が入っている列の並び（1 件以上）で、列の値が並びなら要素ごとに照合する。他のキーの値は列の名前 1 つ
- `type` ごとの `fields` のキーは次のとおり。表に無いキーは許さない

  | type | 必須の fields | 任意の fields |
  | --- | --- | --- |
  | term | id・match・description | title・related・avoid |
  | doc | id・match・description | title |
  | command | id・match・command | title・description・cwd |
  | url | id・match・url | title・description |

- 各キーに `title`・`description` と、`aliases[]` の要素の `examples` を書く
- `id` の一意はスキーマで表せないため、読む側が確かめる

### バージョン

alias-inject のリリースのタグ（`v{バージョン}`）を、スキーマのバージョンにする。
スキーマのファイルに独自のバージョンは持たせない。
取り込む側はタグを指定して `schemas/aliases.schema.yaml` を取り込み、取り込んだタグを記録する（取り込みの方法は取り込む側の Issue で決める）。

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | リリースのタグをスキーマのバージョンにする | バージョンの出所が 1 つで、タグの URL で取り込める | スキーマが変わらないリリースでもタグが進む |
| B | スキーマに独自のバージョン（`x-version`）を持たせる | スキーマの変更だけでバージョンが進む | タグとスキーマのバージョンの 2 つを対応させて管理する |

推奨: A

Issue の参考の一案（タグで固定して取り込む）に沿い、取り込む側はタグだけを記録すればよい。

### スキーマの確かめ方

スキーマの中身と JSON Schema としての正しさは、レビューで確かめる。
単体テストは置かない。
alias-inject 自身が設定をスキーマで検証するのは [#9](https://github.com/shuhei1101/alias-inject/issues/9) で、検証器が要るかはそこで決まる。

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| 設定の `sources[]` を `aliases[]` の構造に合わせ、`dev-docs.yaml` の `aliases[]` を読む | 今回の変更を前提にした後続 | [#9](https://github.com/shuhei1101/alias-inject/issues/9) |
| 設定の `doc` の `mcp`（共通の構造の `fields` に無い） | 設定を共通の構造に合わせるときに扱いが決まる | [#9](https://github.com/shuhei1101/alias-inject/issues/9) |
| mdmark でのスキーマの取り込みと YAML のエイリアスの登録 | 他のリポジトリの後続 | [shuhei1101/mdmark#125](https://github.com/shuhei1101/mdmark/issues/125) |
| dev-docs でのスキーマの取り込み | 他のリポジトリの後続 | [shuhei1101/dev-docs#3](https://github.com/shuhei1101/dev-docs/issues/3) |
| 引用の種類 skill・tool・path・env・avoid の追加 | 要望は最初の 4 種類 | [#12](https://github.com/shuhei1101/alias-inject/issues/12) |
