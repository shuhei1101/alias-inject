# 要件

## 要望

Claude Code が書き込む内容と、Claude Code の応答の文に出た単語にも、入力・ツールの結果と同じ設定と単語で照合して引用の文脈を追加する。

- 終わりの条件: 単語を含む内容を Write・Edit で書き込ませると、その会話で初めて出た単語の引用の文脈がモデルに届く
- 終わりの条件: 単語を含む応答の文を回答させると、その会話で初めて出た単語の引用の文脈がモデルに届く
- 追加した単語の記録は入力・ツールの結果と共有し、どれかで一度追加した単語はもう追加しない
- 照合・照合条件・作業場所の絞り・上限・文脈の書式は、今のツールの結果の照合と同じにする

`未確定`: 応答の文に文脈を追加できるイベント（決める段: PoC 検証）

hooks モジュールに応答の文を受けて文脈を返却できるイベントがあるかを確認していない。
イベントが無いと分かった場合は、応答の文の照合を除外する要件の縮小になるので、ユーザーに確認する。

`未確定`: 照合する書き込む内容の範囲（決める段: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `exclude_tools` に無い全てのツールの引数の文字列の値を照合する | MCP の書き込みのツールを列挙せずに済み、新規のツールにも有効 | Read の `file_path`・Bash の `command` など、書き込みでない引数の単語でも文脈が追加される |
| B | 書き込みのツール（Write の `content`・Edit の `new_string` など）を列挙し、その引数だけを照合する | 書き込む内容だけに絞れる | MCP の書き込みのツールを列挙して保つ必要がある |

推奨: A

Issue の依頼はモデルが出力した文字列全てでの照合で、ツールの引数はどれもモデルが出力した文字列のため。

`未確定`: 書き込む内容を照合する時点（決める段: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `tool.call` で `next(e)` の後に、成功した結果の後ろの文脈へ追加する | 今のツールの結果の文脈と同じ位置に届き、書き込みが失敗した内容では追加しない | ツールの実行が終わるまで文脈が届かない |
| B | `next(e)` の前に引数を照合する | ツールの実行の前に照合できる | 文脈を届ける場所が結果の後ろしか無く、照合の結果を持ち越す処理が増える |

推奨: A

`tool.call` が文脈を返却できるのは結果の `context` だけで、前で照合しても届けるのは後になるため。
