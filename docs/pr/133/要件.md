# 要件

## 要望

入力（`prompt.submit`）とツールの結果（`tool.call`）で単語がヒットし、引用の文脈を追加したときに、追加した単語と文書の ID を利用者の画面に表示する。

- 表示するのは、その回に `context` へ追加した単語だけにする（記録済みで追加しなかった単語は表示しない）
- 文脈を追加しなかった回（ヒットが無い・全て記録済み・無効の設定）は何も表示しない
- 表示は、モデルへの入力（入力の文と `context`）を変えない
- 表示に失敗しても、入力の送信とツールの結果は止めない

表示に使用する Claude Code の機能は、PoC 検証で案 A（`$.ui.log` の `to: 'transcript'`）に確定した（[プラグイン](./プラグイン.md) の `## PoC 結果`）。

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `$.ui.log` を `to: 'transcript'` で呼び、会話の記録に出す | 採用済みの API（[claude-code](../../library/LIB-1.yaml)）の範囲で済む | 会話の記録に出た文字列がモデルの入力に入らないかが未検証 |
| B | 他の表示の API（通知・ステータスの表示など）を使用する | 会話の記録を汚さない | 型の宣言にあるかが未確認 |

推奨: A

採用済みの API に会話の記録へ出す先があり、モデルに入らないことを PoC で確認すれば足りるため。

`未確定`: 表示する量（決める工程: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 追加した単語を全て、単語と文書の ID の 1 行にまとめて表示する | どの単語が追加されたかを全て確認できる | 単語が多いと 1 行が長くなる |
| B | 追加した単語の数だけを表示する | 画面を占めない | どの単語かが分からない |

推奨: A

追加する単語の数は既に `max_items` で上限があり、利用者の依頼はどの単語がヒットしたかを確認することのため。

`未確定`: 表示のオンとオフの設定（決める工程: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 設定ファイルの `global`・`projects` に表示のオンとオフのキーを追加する（既定はオン） | 表示が要らない利用者・プロジェクトで止められる | 設定のキーと検証が増える |
| B | 設定を追加せず、常に表示する | 設定が増えない | 止める手段が無い |

推奨: A

既存の設定が `enabled`・`origins` をプロジェクトごとに上書きできる作りで、表示の要否もプロジェクトごとに分かれるため。

表示の文面は、ユーザーの目に触れる語彙のため、インターフェース定義設計でユーザーに確認する。
