# 要件

## 要望

テスト実行方法の層ごとに、判定フローチャート『テストの実行場所』で実行場所（`runner` / `local`）を決めて記載し、`runner` の層を GitHub Actions の workflow で回せるようにする。

- 終わりの条件
  - `docs/test-procedure/TP-1.yaml` の全ての層が `location` を持つ
  - `location` が `runner` の層が、workflow を `workflow_dispatch` で起動して終わるまで待ちログを取得する `run_runner` を持ち、手元で回す `run_all` も残している
  - `.github/workflows/test.yml` が、`runner` の層の全件を回す
  - workflow のインターフェース定義が、レビューに合格してから workflow を作っている
  - lint の層が actionlint を含み、手元の lint の全件実行が合格する
  - この作業 PR のテストは手元の全件実行で回し、ランナーで回さない理由をログに記録している（`workflow_dispatch` は develop にある workflow だけを起動できるため）

プラグインの利用者の操作と振る舞いは変えないため、影響するユースケースは無い。

workflow は入力を持たない 1 つにし、単体テスト（TL-1）と結合テスト（TL-2）の `run_runner` から同じ workflow を起動する。
2 つの層はどちらも `claude plugin test .` で全てのテストを同時に回し（ファイルを指定できない）、層を指定する入力を持っても workflow の中で使う値が無いため。
