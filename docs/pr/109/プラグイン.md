## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 単体（TL-1）・結合（TL-2）の実行場所 | `runner`。lint ではなく、手元でしか用意できないもの・外部のサービスへの接続を使わず、足りない道具（Node.js・Claude Code）は workflow の中で npm で入れられるため | - |
| E2E（TL-3）・非機能要件（TL-4）・外部疎通（TL-5）の実行場所 | `local` のまま。`run_all` が未確定でテストも無く、判定の材料が無い | テストを作る作業で判定し直す |
| lint（TL-6）の実行場所 | `local`（判定フローチャートの lint の分岐） | - |
| lint の全件実行 | actionlint を加える。どれかが失敗しても全ての検査を最後まで回す今の形を保つ | actionlint は手元に無いため、前提と入れ方を CMD-1・TP-1 に記載する |
| workflow のインターフェース定義 | `docs/interface/IF-6.yaml` を新しく作り、入口 `trigger`（`workflow_dispatch`）・権限・排他・step の全ての分岐と結末を記載する | 起動の単位は `未確定`（`要件.md`） |
| workflow | `.github/workflows/test.yml`。`ubuntu-latest` で Node.js と Claude Code を入れ、`claude plugin test .` を回し、成否によらずログを成果物に上げる | 起動は `workflow_dispatch` だけで、push・PR を契機にしない。タイムアウトは判定フローチャート『タイムアウトの決め方』で決める |
| `run_runner` | `gh workflow run` で今のブランチの workflow を起動し、`gh run watch` で終わるまで待ち、`gh run view --log` でログを取得する 1 コマンドを TL-1・TL-2 に記載する | - |
| この作業 PR のテスト | 手元の全件実行で回し、ランナーで回さない理由をログに記録する | ランナーでの初回と skip の件数の比較はスコープ外 |
