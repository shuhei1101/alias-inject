## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 実行器 | Node の組み込みのテストランナー（`node --test`）で `tests/e2e/workflow/test-yml.e2e.ts` を実行する。TL-3 の `run_all`・`run_one`・`prerequisites` と `location: local` を記載する | ファイル名を `*.test.ts` にすると `claude plugin test`（単体・結合の全件実行）が拾い、検証用のブランチの push まで走るため、`*.e2e.ts` にする |
| IF-6 | `test_file` を `tests/e2e/workflow/` のファイルにし、`flows[].test` を `test_normal`・`test_error_when_{原因}` で記載する。`notes` の確認方法を改める | knowledge の規約『V字モデル』 |
| 検証用のブランチ | テストの関数ごとに作業ブランチの commit から作り、フローの `setup` のとおり書き換えて push し、テストの後に成否によらず削除する。名前にテストの関数名と実行の時刻を含める | 異常系は、fail するテスト・同期の無限ループで止まるテスト・存在しない Claude Code のバージョンを、検証用のブランチにだけ入れる |
| 起動と照合 | `gh workflow run test.yml --ref {ブランチ}` で起動し、`gh run watch` で待ち、`gh run view --json conclusion,jobs` の結論と step ごとの結論をフローの図と `expected` に照合する。成果物は `gh run download -n test-log` で取得する | 実行の ID の取り方は TP-1 の `run_runner` と同じにする |
| LIB-4 | 異常系の実行で観測できたキーの `verification_state` と `verification` を記録する | - |
| LAY-1 | `tests/e2e/workflow/` を記載する | - |
| 型検査 | lint の `npm run typecheck` は `tests/` の全てを含み、Node の型（`node:test`・`node:child_process`）の宣言を持たないため、Node の型の宣言（`@types/node`）を devDependencies に完全一致で追加し、E2E のフォルダだけが参照する型検査の設定（`tests/e2e/tsconfig.json`）を加える | 既存の型検査の設定からは E2E のフォルダを除外し、hooks モジュールが Node の型を参照しないようにする |
