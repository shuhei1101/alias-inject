# 要件

## 要望

E2E の層（TP-1 の TL-3）の実行器を決め、IF-6 の 4 つのフローを本物の GitHub Actions で起動して確認するテストを `tests/e2e/workflow/` に作る。

- 終わりの条件
  - TL-3 の `run_all`・`location`・`prerequisites` を記載している（`location` は、検証用のブランチを本物のリポジトリへ push するため `local`）
  - IF-6 の `test_file` を `tests/e2e/workflow/` のファイルにし、`flows[].test` をフローごとに記載している。`notes` の「結合テストのファイルは持たない」を、E2E テストで確認する旨に改めている
  - テストの関数がフローごとに 1 つあり、検証用のブランチの用意と削除・`gh workflow run` での起動・実行の結論と step ごとの結論の照合・成果物 `test-log` の確認をする
  - 4 つのテストを手元で回して全て pass し、そのログを PR ドキュメントの `テスト結果/` に配置している
  - テストを回した後に、検証用のブランチがリモートに残っていない
  - 異常系の実行で観測できた GitHub Actions のキー（`if: always()`・`timeout-minutes`・`if-no-files-found: warn`・`concurrency`）の LIB-4 の `verification_state` を記録している
  - フォルダ構成 LAY-1 に `tests/e2e/workflow/` を記載している

プラグインの利用者の操作と振る舞いは変えないため、影響するユースケースは無い。

E2E の実行器は、Node の組み込みのテストランナー（`node --test`）にし、テストを TypeScript で記載する（インターフェース定義設計で決めた）。
