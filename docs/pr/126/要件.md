# 要件

## 要望

- 検索の対象を、setup の既定（`**/*`。`.git`・`node_modules`・`.claude/worktrees` の下と、Git が無視するファイルは除く）に合わせる
  - 配信元のフォルダで `/project-index:setup` を実行し、対象に入っていないフォルダ（直下・`.claude-plugin/`・`.github/`・`hooks/`・`schemas/`・`scripts/`・`skills/`・`tests/`・`types/`・`docs/` 直下・`docs/_theme/`）ごとに管理用の YAML を配置して、`documents[]` に行を加える
  - 設計書のフォルダ（`docs/{種類}/`）の `README.md` は、そのフォルダの管理用の YAML に記載する
  - `project-index files` が記載しないファイル（バイナリ・空のファイル・`*.local.*`）は対象に入れない
- 既存の管理用の YAML（`docs/guide/files.yml`）の行のメタデータを、setup の付け方（段階的に中身を参照して付ける・`project-index skew` で偏りを洗い出す）で見直す
  - `docs` の行の `exclude` が除外している `docs/guide/` の `README.md`・`はじめに.md`・`使い方.md`・`リファレンス.md` も行に記載する
- 見直した後に `project-index checkpoint` で確認の時点を記録し、`check_project` で索引の同期の件数（管理用の YAML に無いファイル・ファイルが無い行・`metadata` の列が無い文書）が 0 であることを確認する

`未確定`: PR ドキュメント（`docs/pr/`）を検索の対象に入れるか（決める段: 実装のレビュー）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `docs/pr/` を対象に入れる | setup の既定（`**/*`）と一致し、過去の PR の要件・計画も検索できる | 300 件を超える行とメタデータが増え、ログの行が検索の結果に混ざる |
| B | `documents[].exclude` で `docs/pr/` を対象から除外する | 検索の結果が今の設計書・公開ドキュメント・コードに絞られる | setup の既定と違う値を持ち、過去の PR の経緯は検索できない |

推奨: B

決定した内容は設計書・公開ドキュメントへ反映され、[shuhei1101/project-index#132](https://github.com/shuhei1101/project-index/pull/132) も同じ判断で対象に入れていないため。
