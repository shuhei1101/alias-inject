## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| Mermaid の図 | `write_docs` の `text_edits` で、範囲の外の ```` ```mermaid ```` を `<!-- map -->` 〜 `<!-- /map -->` で囲み、図の外の補足を `map-data` の注釈へ移す | 図の種類は規約『表し方の優先順位』の伝えるものと図の種類の表で選ぶ |
| 判定フローチャート | 公開ドキュメント『エイリアスを登録するかを決める』の図と注釈を削除し、knowledge の判定フローチャート『エイリアスの登録』へのリンクにする | - |
| 表 | 同じ属性を持つ項目が 2 件以上ある文・箇条書きを表にし、6 行以上の表を `<!-- table: {"kind": "data"} -->` で囲む | - |
| 文 | 既出の言い直し・理由の説明・当たり前の注意を削除する | 規約『既存文章の維持』に従い、削除と表への移動の他の言い回しは変えない |
| タグ | `group_by: tags`（`source: "*"`）で既存のタグを確認し、規約『文書のタグと description の記載』に従って付ける | - |
| `description` | 「何を定め、どんなときに参照するか」の 1 文にする | 公開ドキュメントは `files.yml` の行に記載する |
| エイリアスと用語 | 判定フローチャート『エイリアスの登録』『用語の登録』で判定し、`aliases` と用語集（`alias_type`）へ登録する | - |
| 関連 | 管理用の YAML のコード・テストの行に、判定フローチャート『関連の張り方』に従って `implements`・`tests` を張る | - |
| 本文の ID・番号・パス | 検討事項の ID は関連のキーへ、Issue 番号・文書のパスはタイトル付きのリンクへ移す | - |
| 検査 | `write_docs` の検査、mdmark の `check`、dev-docs の画面での描画の確認 | - |
