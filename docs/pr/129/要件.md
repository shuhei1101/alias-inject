# 要件

## 要望

配信元 alias-inject の文書（`docs/pr/` を含む `docs/` の文書と、直下の文書）を、次の工程で移行する。

| 工程 | 完了の条件 |
| --- | --- |
| 棚卸し | project-index の `search_docs` で、Mermaid・接頭辞の無いタグ・空か規約に合わない `description`・本文に生の文字で記載した検討事項の ID と Issue 番号とパスを含む文書の一覧を作る |
| 図の置き換え | 本文の ```` ```mermaid ```` を mdmark の map の範囲（`<!-- map -->` 〜 `<!-- /map -->`）の中に移し、範囲の外に Mermaid が残らない |
| 文を表へ | 同じ属性を持つ項目が 2 件以上ある文・箇条書きが表になっている |
| 文の削除 | 既出の言い直し・理由の説明・当たり前の注意を削除し、残す文が規約『文章の書き方』の確認表に当てはまらない |
| メタデータの再設定 | 全ての文書のタグが `action:`・`topic:`・`tool:`・`scope:` の接頭辞を持ち、`main` が 1 つ付く。`description` が「何を定め、どんなときに参照するか」の 1 文になる。エイリアスと用語を knowledge の判定フローチャート『エイリアスの登録』『用語の登録』で判定して登録する |
| 本文に出さないものの移動 | 検討事項の ID は関連のキーへ、Issue 番号・文書のパスはタイトル付きのリンクへ移す |
| 設計書とコードの関連 | 管理用の YAML のコード・テストの行に、設計書への `related`（`implements`・`tests`）を張る |
| 判定フローチャートの参照 | 公開ドキュメント『エイリアスを登録するかを決める』の図を削除し、knowledge の判定フローチャート『エイリアスの登録』を参照する記載にする |
| 検査 | `write_docs` の検査と mdmark の `check` を通り、画面で描画して図が重ならずに参照できる |

AI slop の単語の置き換えは [#88](https://github.com/shuhei1101/alias-inject/issues/88) で行う。
