# 要件

## 要望

knowledge のテンプレート『フォルダ構成』（`template-layout`）の書式で、このリポジトリのフォルダ構成の設計書を `docs/layout/` に 1 枚作り、project-index で配信する。
規約『フォルダ構成の切り方とレビュー』（`dev-folder-layout`）のレビューの観点で今のフォルダ構成を確認し、見つかった問題は観点ごとに別の Issue へ起票する。

- 終わりの条件
  - 設計書が、リポジトリの直下からの git が管理する全てのフォルダとファイルを、入れ子の `entries[]` で記載している（言語の規約が配下を定めるフォルダは `convention` で指し、`children` を記載しない）
  - 生成物・一時ファイル（`.gitignore` の `docs/generated/`・`node_modules/`・`__pycache__/`）を `gitignore[]` に、リポジトリの中に生成元を持つ生成物のエントリ（`hooks/lib/aliases-schema.ts`）を `generated_from` つきで記載している。リポジトリの外を元にする複製（`hooks/vendor/`・`docs/_theme/`）はスコープ外の行で扱う
  - `project-index.yaml` の `documents` に、knowledge の `schemas/design/layout.schema.yaml` を指すフォルダ構成の行があり、設計書がそのスキーマの検査に合格する
  - レビューの観点の表の観点ごとに、確認した結果（問題の有無）と、問題を起票した Issue の番号が PR ドキュメントにある
- 問題の対処（フォルダの移動・削除）は、この PR では行わない
