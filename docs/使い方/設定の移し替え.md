# 設定の移し替え

端末の設定と dev-docs.yaml を、`metadata.alias_type` の構造と旧い `aliases[]` の構造（`type`・`fields`）から、行の `alias_type` と列名の `metadata` の構造へ移し替える手順

## 前提

`metadata.alias_type` の構造（`{type: ref, field}`・`{type: custom, value}` の値を含む）と、旧い `type`・`fields` の構造は読まない。
移し替えるまでは、これらの構造の要素は照合から外れ、外した理由が Claude Code の debug log に出る。
dev-docs.yaml のトップレベルの `aliases` も読まない。

新しい構造は [エイリアスのスキーマ](../リファレンス/エイリアスのスキーマ.md)、設定の項目は [設定ファイル](../リファレンス/設定ファイル.md) を参照する。

## 手順

<!-- steps -->

1. 設定ファイルのバックアップをコピーする。

   ```bash
   mkdir -p ~/.config/alias-inject/bk
   cp ~/.config/alias-inject/settings.yaml ~/.config/alias-inject/bk/settings.yaml
   ```

2. 設定ファイルの `global.aliases` と `projects[].aliases` の要素を、[書き換えの対応](#書き換えの対応) で新しい構造に書き換える。

3. 読むリポジトリの `dev-docs.yaml` の `documents` の行のうち `metadata.alias_type` を持つ行を、同じ対応で書き換える。
   トップレベルの `aliases` の要素は、同じ対応で `documents` の行に移し、トップレベルの `aliases` を削除する。

4. `paths` が指す YAML の最上位が並びのものは、並びを 1 つのキーの下に移し、その行の `records` にキーの名前を指定する。
   1 件ずつ別のファイルにする場合は、`records` を指定しない。

5. 用語を含む文を Claude Code に入力し、モデルに追加される文脈にその用語が出ることを確かめる。
   設定ファイルと dev-docs.yaml に `fields`・`metadata.alias_type` が残っておらず、debug log に要素を外した理由の行が出ていないことも確かめる。

<!-- /steps -->

## 書き換えの対応

`metadata.alias_type` の構造から移すときの対応。

| `metadata.alias_type` の構造 | 新しい構造 |
| --- | --- |
| `id`・`enabled`・`paths`・`records` | そのまま |
| `metadata.alias_type`。`{type: custom, value: 値}` | 行の `alias_type`。値 |
| `metadata.alias_type`。`{type: ref, field: 列の名前}` | 新しい構造では文書ごとに種類を変えられない。種類ごとに行を分け、それぞれの行の `alias_type` に種類を指定する |
| `metadata` の他のキー。`{type: ref, field: 列の名前}` | 同じキーに列の名前の文字列。列の名前がキーと同じなら記載を省く |
| `metadata` の他のキー。`{type: custom, value: 値}` | 新しい構造では行で固定できない。値を YAML の列に記載し、同じキーにその列の名前の文字列を指定する |

旧い `type`・`fields` の構造から移すときの対応。

| 旧い構造 | 新しい構造 |
| --- | --- |
| `id`・`enabled`・`paths` | そのまま |
| `type` | 行の `alias_type`。旧い `type` の値 |
| `fields.title` の列 | `metadata.name`。列の名前の文字列 |
| `fields.match` の最初の列（`fields.title` が無いとき） | `metadata.name`。列の名前の文字列 |
| `fields.match` の列のうち `metadata.name` にしなかった列 | `metadata.aliases`。列の名前の文字列 |
| `fields.id`・`description`・`related`・`avoid`・`command`・`cwd`・`url`・`skill`・`tool`・`path`・`port`・`replacement` | 同じ名前の `metadata` のキー。列の名前の文字列 |

- `metadata` のキーは、記載しなければ同じ名前の列から取る。列の名前がキーと同じなら記載を省ける
- 入れ子の列は `meta.summary` のように `.` でつなぐ
- 照合する語は `name` と `aliases` の 2 つの列に限る。`metadata.aliases` にする列が 2 つ以上あるときは、YAML の値を 1 つの列にまとめる

## 移し替えの例

旧い `type`・`fields` の構造。

```yaml
global:
  aliases:
    - id: terms
      type: term
      paths:
        - terms/*.yaml
      fields:
        id: id
        match:
          - name
          - aliases
        description: description
        related: related
```

`metadata.alias_type` の構造。

```yaml
global:
  aliases:
    - id: terms
      paths:
        - terms/*.yaml
      metadata:
        alias_type:
          type: custom
          value: term
        name:
          type: ref
          field: title
```

新しい構造。

```yaml
global:
  aliases:
    - id: terms
      paths:
        - terms/*.yaml
      alias_type: term
      metadata:
        name: title
```

`id`・`aliases`・`description`・`related` は、同じ名前の列から取る。
旧い `type`・`fields` の構造の例では、`name` も同じ名前の列から取るので、`metadata` を記載しない。
dev-docs.yaml は、同じ内容を `documents` の行にする。

```yaml
documents:
  - id: terms
    paths:
      - terms/*.yaml
    alias_type: term
    metadata:
      name: title
```
