# セットアップ

前提条件と、マーケットプレイスからユーザースコープで入れて、設定ファイルを用意する手順

## 前提条件

| 項目 | 内容 |
| --- | --- |
| OS | Linux（WSL2 を含む） |
| Claude Code | ターミナル版のバージョン 2.1.310 以上 |

動作を確かめているのは上の OS とバージョンだけで、新しいバージョンでの動作は保証しない。

## 手順

<!-- steps -->

1. マーケットプレイスを登録する。

   ```bash
   claude plugin marketplace add shuhei1101/alias-inject
   ```

2. ユーザースコープでプラグインを入れる。

   ```bash
   claude plugin install alias-inject@alias-inject --scope user
   ```

3. プラグインの一覧で、入ったことを確かめる。

   ```bash
   claude plugin list
   ```

   `alias-inject@alias-inject` が `Scope: user`・`Status: enabled` で出れば完了する。

<!-- /steps -->

## 設定ファイルを用意する

プラグインを入れただけでは、何も追加しない。
読むリポジトリの `dev-docs.yaml` や照合する YAML を指定した設定ファイルを用意し、そのパスを `ALIAS_INJECT_CONFIG` に指定する。

<!-- steps -->

1. 設定ファイルを置くフォルダを作り、リポジトリの `settings.sample.yaml` をコピーする。

   ```bash
   mkdir -p ~/.config/alias-inject
   curl -fsSL https://raw.githubusercontent.com/shuhei1101/alias-inject/master/settings.sample.yaml -o ~/.config/alias-inject/settings.yaml
   ```

2. コピーした `~/.config/alias-inject/settings.yaml` を編集し、`repositories` の `config` に読むリポジトリの `dev-docs.yaml` のパスを指定する。
   端末だけのエイリアスは `aliases` に記載し、`paths` に照合する YAML のパスを指定する。
   項目は [設定ファイル](../リファレンス/設定ファイル.md) を参照する。

3. `~/.claude/settings.json` の `env` に `ALIAS_INJECT_CONFIG` を追加し、設定ファイルのパスを指定する。

   ```json
   {
     "env": {
       "ALIAS_INJECT_CONFIG": "~/.config/alias-inject/settings.yaml"
     }
   }
   ```

   読むのはユーザースコープの `settings.json` だけで、プロジェクトスコープの `env` は読まない。

4. Claude Code で、`aliases` の `paths` に挙げた YAML にある用語を含む文を入力し、モデルの回答にその用語の説明が反映されることを確かめる。

   設定ファイルや `dev-docs.yaml`、YAML が読めないときは、入力の送信は止まらず、読めなかったパスと理由が Claude Code の debug log に出る。

<!-- /steps -->
