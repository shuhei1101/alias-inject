# 引用の文脈

入力の語を YAML と照合し、モデルにだけ文脈を追加する仕組み

## 何が起きるか

入力を送信するたびに、入力の文に含まれる語を、読むリポジトリの `dev-docs.yaml` の `documents` の行と設定ファイルの `aliases` の行が指す YAML の用語・エイリアスと照合する。
当たった語の説明（意味・文書の ID・コマンド・URL など）を引用の文脈としてまとめ、モデルにだけ追加する。
入力の文は変えずにそのまま渡す。

ツールの結果（Bash・Read・MCP のツールなど）の本文も、同じ設定と語で照合し、当たった語の引用の文脈をツールの結果の後ろに追加する。
本文は変えない。
ツールの結果は `origins` で絞らない。

次の入力は照合しない。

- スラッシュコマンドの行
- 設定の `origins` に無い出所の入力
- 設定ファイルが無い・読めないとき、`enabled` が `false` のとき

次のツールの結果は照合しない。

- 設定の `exclude_tools` に名前が完全に一致するツールの結果
- エラーの結果・他のフックが拒んだ呼び出し・本文の無い結果

照合で例外が起きても、ツールの結果は止めずに返す。

設定ファイルや `dev-docs.yaml`、YAML が読めないときも、入力の送信は止めない。
読めなかったパスと理由は、Claude Code の debug log に出る。
読めない `dev-docs.yaml` は、そのリポジトリの定義だけを照合から外す。
`documents` の行や `aliases` の要素がスキーマに合わないときも、その行だけを外す。
`documents` の行が `alias_type` を持たず `metadata.alias_type` を持つ旧い構造のときも、その行だけを外し、移し替えが要る理由を debug log に出す。
必須のキーの値が空の文書も、その文書だけを外す。

## 照合

照合するのは、行の `metadata` が指す列の `name` と `aliases` の値（用語とエイリアス）だけ。
`aliases` の値が並びなら、要素ごとに照合する。
`name` が空の文書は、ファイル名（拡張子を除く）を使う。`records` を指定した行の要素は、行の `body_file` が指す列の値のファイル名（拡張子を除く）、それも空なら `id` を使う。

照合の前に、入力と語の両方を次のようにそろえる。

- NFKC で正規化する
- 英字を小文字にする
- 前後の空白を除く

そろえた語が、そろえた入力の部分文字列に含まれれば当たる。
正規表現は使わない。
`exclude` に挙げた語は照合しない。

1 つの項目の複数の語（用語とエイリアス）が当たっても、その項目は 1 回だけ追加する。
`global` と当たった `projects` の `aliases` の行と、読む全てのリポジトリの `documents` の行を照合するので、別の行にある同じ語は、どちらも追加する。

ツールの結果では、読んでいる文書そのものの語を追加しない。

| ツール | 外す語 |
| --- | --- |
| Read | 語の指す文書のパスが、読んだファイルのパス（`file_path`）と一致する語 |
| MCP のツール（`mcp__` で始まる名前） | 文書の `id` が、ツールの引数の文字列の値（入れ子の値を含む）と一致する語 |

語の指す文書のパスは、`records` を書かない行では語を取り出した YAML、`body_file` を書いた行では `body_file` の列の値のパスになる。

## 1 セッション 1 回

追加した項目は、セッション ID に紐づけて記録する。
記録は入力とツールの結果で共有するので、どちらかで一度追加した項目は、もう一方でも追加しない。
サブエージェントのツールの結果は、セッション ID とサブエージェントの ID の組で別に記録する。
サブエージェントで追加した項目は、メインの会話では追加済みにならない。
記録の単位は、定義の出所（`dev-docs.yaml` か設定ファイルの絶対パス）と行の `id` と文書の `id` の組なので、同じ項目をエイリアスで入力しても二度目は追加しない。
別のリポジトリが同じ行の `id` と文書の `id` を使っても、それぞれを追加する。

記録は次のときに削除する。
削除した後に同じ語を入力すると、文脈をもう一度追加する。

| きっかけ | 削除するか |
| --- | --- |
| 会話の圧縮（手動・自動・プラグインによる圧縮） | 削除する |
| `/clear` | 削除する |
| `claude --resume` で戻ったセッション | 削除しない。追加済みの文脈が会話に残っているため |
| サブエージェントの圧縮 | そのサブエージェントの記録だけを削除する |
| 圧縮の事前の計算 | 削除しない |

## 追加する量の上限

1 回に追加する語は `max_items` 語、文脈全体は `max_chars` 文字までで、既定は 20 語と 4,000 文字。
入力に最初に出た位置の早い語から順に選び、同じ位置なら長い語を先に選ぶ。
ツールの結果では、本文に出た回数の多い語から順に選ぶ。
同じ回数なら、最初に出た位置の早い語、同じ位置なら長い語を先に選ぶ。
`max_chars` を超える語は飛ばして、後ろの語で収まるものを続けて選ぶ。
選ばれなかった語は、その回に追加せず記録にも入れないので、次に出た入力で追加の対象になる。

## 引用の種類

行の `alias_type` が、追加する列を決める。
列の値は、行の `metadata` が列名で指す文書の列から取り、`metadata` に記載しないキーは同じ名前の列から取る。入れ子の列は `meta.summary` のように `.` でつなぐ。

| alias_type | 追加する列 |
| --- | --- |
| `term` | 語・`id`・`description`・`related`（関連する文書の ID と名前） |
| `doc` | 語・`id`・`description` |
| `command` | 語・`id`・`command`・`cwd`・`description` |
| `url` | 語・`id`・`url`・`description` |
| `skill` | 語・`id`・`skill`・`description` |
| `tool` | 語・`id`・`tool`・`description` |
| `path` | 語・`id`・`path`・`description` |
| `env` | 語・`id`・`url`・`port`・`description` |
| `avoid` | 語・`id`・`replacement` |

## 文脈の書式

文脈は `heading` の見出しの下に、`alias_type` ごとのセクションと、語ごとの箇条書きで並べる。
セクションの見出しは `alias_type` ごとに固定で、`term` が `用語`、`doc` が `文書`、`command` が `コマンド`、`url` が `URL`、`skill` が `スキル`、`tool` が `ツール`、`path` が `パス`、`env` が `環境`、`avoid` が `避ける語`。
並びはこの順で、同じ `alias_type` の語は、リポジトリや行が違っても 1 つのセクションにまとめる。
語は `name` の値。
箇条書きの子には、`alias_type` ごとの列のうち値のあるものだけを並べる。

```markdown
# この発言に出る用語

## 用語

- 単一ユースケース（id: term-single-usecase）
  - description: 1 つの操作を始めから終わりまで記載するシナリオの単位
  - related: tpl-scenario（シナリオのテンプレート）

## コマンド

- セットアップ（id: cmd-setup）
  - command: `uv sync`
  - cwd: /mnt/c/Users/shuhe/repo/ai-monitor
  - description: 依存を入れる
```

設定ファイルの項目は、[設定ファイル](../../リファレンス/設定ファイル.md) を参照する。
