# エイリアスのスキーマ

エイリアスの元の行のキー・`metadata` の値・`alias_type` ごとのキー・タグを指定した取り込み方

## スキーマの場所

用語・文書のエイリアス・コマンド・URL・スキル・ツール・パス・環境・避ける語を「どの YAML のどの列から取るか」を定義する共通の構造「エイリアスの元の行」のスキーマは、リポジトリの `schemas/aliases.schema.yaml` にある。
書式は JSON Schema（2020-12）を YAML で書いたもの。
行は dev-docs.yaml の `documents` の行と同じ構造で、mdmark・dev-docs も同じ行を読む。
mdmark・dev-docs はこのスキーマだけを取り込み、alias-inject のコードには依存しない。
alias-inject も、このスキーマで端末の設定の `aliases` と、読むリポジトリの `dev-docs.yaml` の `documents` のうち `metadata.alias_type` を持つ行を検証する。
スキーマに合わない行は照合から外し、出所・`id`・理由を debug log に出す。
検証には、このスキーマから生成して同梱する `hooks/lib/aliases-schema.ts` を使う。
設定の項目は [設定ファイル](./設定ファイル.md) を参照する。
スキーマを変えるときは alias-inject に Issue を立てて変える。

ルートは行の並びで、行の定義は `$defs` にある。
取り込む側は、エイリアスの元の行を並べるキーからルートを `$ref` で指す。

## 行のキー

| キー | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `id` | string | 必須 | 行の主キー。一意かどうかはスキーマで表せないため、読む側が確かめる |
| `enabled` | boolean | - | `false` のとき使わない。既定は `true` |
| `paths` | string の並び（1 件以上） | 必須 | 読む YAML のパスか glob。ファイルと glob を混ぜてよい。当たった各ファイルが 1 件の文書になる |
| `records` | string | - | 文書の並びを持つ配列のキー。記載した行は、ファイルのその配列の各要素を 1 件の文書にする |
| `metadata` | object | 必須 | エイリアスのキーの値の取り方。キーは [metadata の値](#metadata-の値) |

行と `metadata` は、表に無いキーも許す。
dev-docs・mdmark の行が持つ `type`・`schema` や、`metadata` の共通のキー（`tags`・`status` など）は、検証で弾かない。

## metadata の値

`metadata` に記載できるエイリアスのキーは、`alias_type`・`id`・`name`・`aliases`・`description`・`related`・`command`・`cwd`・`url`・`avoid`・`skill`・`tool`・`path`・`port`・`replacement`。
各キーの値は、`type` が判別子の次のどちらか。

| 値 | 意味 |
| --- | --- |
| `{type: ref, field: 列名}` | 文書の `field` の列から取る |
| `{type: custom, value: 値}` | 行の全ての文書に同じ値を使う |

- `alias_type` だけは必ず記載する。記載しないキーは、同じ名前の列の `ref` とみなす
- 照合する語は `name` と `aliases` の値で、文脈に出す語は `name` の値
- `name` が空の文書は、`records` を記載しない行ではファイル名（拡張子を除く）、`records` の要素では `id` の値を使う
- `alias_type` が `custom` のときは、値が下の 9 つのどれかであることをスキーマが確かめる。`ref` のときは、文書ごとに読む側が確かめる
- `alias_type` 以外のキーが必須かどうかは、文書ごとに解決した値が空かで読む側が判定する

## alias_type ごとの metadata のキー

`alias_type` の値は、`term`・`doc`・`command`・`url`・`skill`・`tool`・`path`・`env`・`avoid` の 9 つ。
必須のキーの値が空の文書は、読む側が照合から外す。

| alias_type | 必須のキー | 任意のキー |
| --- | --- | --- |
| `term` | `id`・`name`・`description` | `aliases`・`related`・`avoid` |
| `doc` | `id`・`name`・`description` | `aliases` |
| `command` | `id`・`name`・`command` | `aliases`・`description`・`cwd` |
| `url` | `id`・`name`・`url` | `aliases`・`description` |
| `skill` | `id`・`name`・`skill` | `aliases`・`description` |
| `tool` | `id`・`name`・`tool` | `aliases`・`description` |
| `path` | `id`・`name`・`path` | `aliases`・`description` |
| `env` | `id`・`name` と、`url`・`port` の 1 つ以上 | `aliases`・`description` |
| `avoid` | `id`・`name`・`replacement` | `aliases` |

term の `avoid` は用語ごとのやめた言い方で、`alias_type` が `avoid` の行（やめた言い方と `replacement` の組）とは別に残す。

## バージョンと取り込み方

alias-inject のリリースのタグ（`v{バージョン}`）が、スキーマのバージョンになる。
スキーマのファイルに独自のバージョンは無い。

取り込む側は、タグを指定して `schemas/aliases.schema.yaml` を取り込み、取り込んだタグを記録する。

dev-docs.yaml では、`documents` の行の `metadata` にエイリアスのキーを記載する。
alias-inject はこの行を、各ファイルを 1 件の用語として読む。

```yaml
documents:
  - id: terms
    paths:
      - terms/*.yaml
    metadata:
      alias_type:
        type: custom
        value: term
      name:
        type: ref
        field: title
```
