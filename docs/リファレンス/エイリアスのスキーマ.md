# エイリアスのスキーマ

`aliases[]` の要素のキー・`type` ごとの `fields`・タグを指定した取り込み方

## スキーマの場所

用語・文書のエイリアス・コマンド・URL を「どの YAML のどの列から取るか」を定義する共通の構造 `aliases[]` のスキーマは、リポジトリの `schemas/aliases.schema.yaml` にある。
書式は JSON Schema（2020-12）を YAML で書いたもの。
mdmark・dev-docs はこのスキーマだけを取り込み、alias-inject のコードには依存しない。
スキーマを変えるときは alias-inject に Issue を立てて変える。

ルートは `aliases[]` の並びで、要素の定義は `$defs` にある。
取り込む側は、自分の設定の `aliases` のキーからルートを `$ref` で指す。

## aliases の要素のキー

| キー | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `id` | string | 必須 | 要素の主キー。一意かどうかはスキーマで表せないため、読む側が確かめる |
| `enabled` | boolean | - | `false` のとき使わない。既定は `true` |
| `type` | `term` / `doc` / `command` / `url` | 必須 | 引用の種類 |
| `paths` | string の並び（1 件以上） | 必須 | 読む YAML のパスか glob。ファイルと glob を混ぜてよい |
| `fields` | object | 必須 | 列の対応。キーは [type ごとの fields](#type-ごとの-fields)、値は元の YAML の列の名前 |

## type ごとの fields

`match` は、本文・入力と照合する語が入っている列の並び（1 件以上）。
列の値が並びのときは、要素ごとに照合する。
`match` 以外のキーの値は、列の名前 1 つ。

| type | 必須の fields | 任意の fields |
| --- | --- | --- |
| `term` | `id`・`match`・`description` | `title`・`related`・`avoid` |
| `doc` | `id`・`match`・`description` | `title` |
| `command` | `id`・`match`・`command` | `title`・`description`・`cwd` |
| `url` | `id`・`match`・`url` | `title`・`description` |

表に無いキーは書けない。

## バージョンと取り込み方

alias-inject のリリースのタグ（`v{バージョン}`）が、スキーマのバージョンになる。
スキーマのファイルに独自のバージョンは無い。

取り込む側は、タグを指定して `schemas/aliases.schema.yaml` を取り込み、取り込んだタグを記録する。
