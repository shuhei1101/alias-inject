# 設定ファイル

設定ファイルの項目・既定値・`alias_type` ごとの `metadata` のキーの一覧

## 設定ファイルの場所

設定ファイルは YAML で、パスを `~/.claude/settings.json` の `env` の `ALIAS_INJECT_CONFIG` に指定する。
先頭の `~` はホームに展開する。
読むのはユーザースコープの `settings.json` だけで、プロジェクトスコープの `env` は読まない。
`ALIAS_INJECT_CONFIG` が無いときは、何も追加せずに入力をそのまま渡す。

置き場所の例は `~/.config/alias-inject/settings.yaml`。
入力の送信ごとに、設定ファイルと読むリポジトリの `dev-docs.yaml`、照合する YAML の更新時刻を確かめ、変わったものだけ読み直す。

## 最上位のキー

| キー | 中身 |
| --- | --- |
| `global` | 全てのプロジェクトで使う設定 |
| `projects` | プロジェクトごとの設定。`match` が当たった要素だけを `global` に重ねる |

## global のキー

<!-- table: data -->

| キー | 型 | 必須 | 既定値 | 説明 |
| --- | --- | --- | --- | --- |
| `enabled` | boolean | - | `true` | `false` のときは何も追加しない |
| `repositories` | object[] | - | なし | 読むリポジトリの `dev-docs.yaml`。キーは [repositories の要素のキー](#repositories-の要素のキー) |
| `aliases` | object[] | - | なし | 端末だけのエイリアス。キーは [aliases の要素のキー](#aliases-の要素のキー) |
| `origins` | `user` / `plugin` の並び | - | すべての出所 | 文脈を追加する入力の出所 |
| `max_items` | integer | - | `20` | 1 回に追加する語の上限。1 以上の整数で、それ以外の値は既定を使う |
| `max_chars` | integer | - | `4000` | 1 回に追加する文脈全体（見出しを含む）の文字数の上限。1 以上の整数で、それ以外の値は既定を使う |
| `exclude` | string の並び | - | なし | 照合しない語。入力・語と同じ正規化をしてから比べる |
| `exclude_tools` | string の並び | - | なし | 結果の本文を照合しないツールの名前（`Bash`・`mcp__{サーバー}__{ツール}` など）。名前が完全に一致するツールを外す。書かないときは全てのツールの結果を照合する |
| `heading` | string | - | `この発言に出る用語` | 追加する文脈の先頭に置く見出し |

<!-- /table -->

`origins` の値は次のとおり。
書かないとき、空の並びのとき、許す値が 1 つも無い並びのときは、すべての出所が対象になる。
それ以外の値は無視する。

| 値 | 対象の入力 |
| --- | --- |
| `user` | 利用者の入力。tmux から送る ai-monitor の指示を含む |
| `plugin` | プラグインが送信した入力 |

## repositories の要素のキー

| キー | 型 | 必須 | 既定値 | 説明 |
| --- | --- | --- | --- | --- |
| `config` | string | 必須 | - | 読むリポジトリの `dev-docs.yaml` のパス |
| `enabled` | boolean | - | `true` | `false` のときは、そのリポジトリを読まない |

- `config` の先頭の `~` はホームに展開する。相対パスは、`global` の中なら設定ファイルのフォルダから、`projects` の中なら起動したプロジェクトの直下から解決する
- `dev-docs.yaml` は `documents` の行のうち `alias_type` を持つ行だけを読み、他の行と他のキー（トップレベルの `aliases` を含む）は読まない。`alias_type` を持たず `metadata.alias_type` を持つ行は、旧い構造として照合から外し、移し替えが要る理由を debug log に出す。`documents` を持たない `dev-docs.yaml` は、定義が 0 件のリポジトリとして扱う
- 読めない `dev-docs.yaml` は、そのリポジトリの定義だけを照合から外す。読めなかったパスと理由は debug log に出る
- `dev-docs.yaml` の `documents` の行は、下の [aliases の要素のキー](#aliases-の要素のキー) と同じ構造で、`paths` の相対パスはその `dev-docs.yaml` のフォルダ（リポジトリの直下）から解決する

## aliases の要素のキー

端末の設定の `aliases` の要素も、`dev-docs.yaml` の `documents` の行も、同じ構造（エイリアスの元の行）で記載する。
構造は [エイリアスのスキーマ](./エイリアスのスキーマ.md) の行と同じ。

<!-- table: data -->

| キー | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `id` | string | 必須 | 行の ID。1 つの設定の中で一意にする |
| `enabled` | boolean | - | `false` のときは、その行を使わない。既定は `true` |
| `paths` | string の並び（1 件以上） | 必須 | 読む YAML のパスか glob。ファイルと glob を混ぜてよい |
| `alias_type` | string | 必須 | 引用の種類。行の全ての文書に同じ種類を使う。値は [alias_type ごとの metadata のキー](#alias_type-ごとの-metadata-のキー) の 9 つのどれか |
| `records` | string | - | 文書の並びを持つ配列のキー。記載しないときは、当たった各ファイルを 1 件の文書にする |
| `body_file` | string | - | `records` の要素の本文のファイルのパスを持つ列の名前。`name` が空の要素の名前に、その列の値のファイル名（拡張子を除く）を使う |
| `metadata` | object | - | エイリアスのキーごとの、値を取る文書の列の名前。キーは [metadata の値の取り方](#metadata-の値の取り方) |

<!-- /table -->

- スキーマ `schemas/aliases.schema.yaml` に合わない要素（旧い `type`・`fields` の構造と、`metadata.alias_type` や判別子つきの `metadata` の値を持つ構造を含む）と、先の要素と `id` が重なる要素は、照合から外す。外した要素の出所・`id`・理由は debug log に出る
- `paths` の glob は、`*` がフォルダの区切りを除く任意の文字列、`**` が任意の深さのフォルダに当たる
- `paths` の先頭の `~` はホームに展開する。相対パスは、端末の設定の `global` の中なら設定ファイルのフォルダから、`projects` の中なら起動したプロジェクトの直下から、`dev-docs.yaml` の中ならそのフォルダから解決する
- `paths` に当たった各ファイルが 1 件の文書になる。`records` を記載した行は、ファイルの最上位のその配列の各要素（マッピング）を 1 件の文書にする。配列が無い YAML は、その YAML だけを照合から外す
- 行と `metadata` には、スキーマで定めたキー以外も記載できる（`type`・`schema`・`tags`・`status` など）。照合にも文脈にも使わない

## metadata の値の取り方

`metadata` のキーは `id`・`name`・`aliases`・`description`・`related`・`command`・`cwd`・`url`・`avoid`・`skill`・`tool`・`path`・`port`・`replacement`。
各キーの値は、値を取る文書の列の名前の文字列で記載する（`name: title`）。

- 記載しないキーは、同じ名前の列から取る。入れ子の列は `meta.summary` のように `.` でつなぐ
- `id` の列を持たない要素の並び（`files.yaml`）を読む行は、`id: path` のように ID にする列を記載する
- 照合する語は `name` と `aliases` の値で、列の値が並びなら要素ごとに照合する。文脈に出す語は `name` の値
- `name` が空の文書は、`records` を記載しない行ではファイル名（拡張子を除く）、`records` の要素では行の `body_file` が指す列の値のファイル名（拡張子を除く）、それも空なら `id` の値を `name` に使う
- 必須のキーの値が空の文書は、照合から外す。外した文書の YAML のパス・`id`・理由は debug log に出る
- `avoid` は、term のキーとして用語ごとのやめた言い方を受け付けるが、文脈には使わない。やめた言い方と正しい語の組は `alias_type` が `avoid` の行で記載する

## alias_type ごとの metadata のキー

行の `alias_type` の値は、`term`・`doc`・`command`・`url`・`skill`・`tool`・`path`・`env`・`avoid` の 9 つ。
表に無いキーは、照合にも文脈にも使わない。

| alias_type | 必須のキー | 任意のキー |
| --- | --- | --- |
| `term` | `id`・`name`・`description` | `aliases`・`related`・`avoid` |
| `doc` | `id`・`name`・`description` | `aliases` |
| `command` | `id`・`name`・`command` | `aliases`・`description`・`cwd` |
| `url` | `id`・`name`・`url` | `aliases`・`description` |
| `skill` | `id`・`name`・`skill` | `aliases`・`description` |
| `tool` | `id`・`name`・`tool` | `aliases`・`description` |
| `path` | `id`・`name`・`path` | `aliases`・`description` |
| `env` | `id`・`name` と、`url`・`port` の 1 つ以上 | `aliases`・`description` |
| `avoid` | `id`・`name`・`replacement` | `aliases` |

## alias_type ごとに追加する列

追加する文脈には、どの `alias_type` でも語と `id` を並べる。
続く列は `alias_type` ごとに次のとおりで、値のあるものだけを並べる。
同じ `alias_type` の語は、リポジトリや行が違っても 1 つのセクションにまとめる。

| alias_type | セクションの見出し | 追加する列 | 用途 |
| --- | --- | --- | --- |
| `term` | `用語` | `description`・`related` | 用語。`related` は関連する文書の ID と名前 |
| `doc` | `文書` | `description` | 文書 |
| `command` | `コマンド` | `command`・`cwd`・`description` | コマンド |
| `url` | `URL` | `url`・`description` | URL |
| `skill` | `スキル` | `skill`・`description` | 使うスキル名と説明 |
| `tool` | `ツール` | `tool`・`description` | 使う MCP のツール名と説明 |
| `path` | `パス` | `path`・`description` | ファイルやフォルダのパスと説明 |
| `env` | `環境` | `url`・`port`・`description` | 環境の URL・ポートと説明 |
| `avoid` | `避ける語` | `replacement` | やめた言い方に代えて使う正しい語 |

## projects の要素のキー

| キー | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `match` | string | 必須 | 絶対パスかプロジェクト名 |
| `repositories` | object[] | - | `match` が当たったときに `global.repositories` の後ろへ重ねる読むリポジトリ |
| `aliases` | object[] | - | `match` が当たったときに `global.aliases` の後ろへ重ねるエイリアス |

`match` は次のときに当たる。

| 指定 | 当たるとき |
| --- | --- |
| 絶対パス | 起動したプロジェクトの直下が、そのパスかその配下 |
| プロジェクト名 | リポジトリのフォルダ名が一致する |

worktree は、本体のパスとフォルダ名で見る。

### 重ね方

`projects` の要素は、`global` と同じキーを持てる。
当たった要素を並びの順に `global` へ重ねる。
`repositories`・`aliases`・`exclude`・`exclude_tools` は後ろに追加し、それ以外のキーは置き換える。
同じ `dev-docs.yaml` を `global` と `projects` の両方が指すときは 1 回だけ読み、`aliases` の `id` が先の要素と重なる要素は外す。
別のリポジトリや要素にある同じ語は、どちらも追加する。

## 設定の例

```yaml
global:
  repositories:
    - config: ~/repo/knowledge/dev-docs.yaml
  aliases:
    - id: glossary
      paths:
        - ~/notes/term/*.yaml
      alias_type: term
      metadata:
        name: title
  max_items: 20
  max_chars: 4000
  exclude: [それ]
projects:
  - match: sample
    aliases:
      - id: commands
        paths:
          - docs/command.yaml
        alias_type: command
        records: commands
```

`glossary` の行は、`~/notes/term/` の各 YAML を 1 件の用語にし、`name` だけを `title` の列から取る。
`id`・`aliases`・`description`・`related` は、同じ名前の列から取る。
`commands` の行は、`docs/command.yaml` の `commands` の各要素を 1 件のコマンドにし、`id`・`name`・`command`・`description` を同じ名前の列から取る。
