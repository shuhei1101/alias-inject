# 設定ファイル

設定ファイルの項目・既定値・`type` ごとの列の一覧

## 設定ファイルの場所

設定ファイルは YAML で、パスを `~/.claude/settings.json` の `env` の `ALIAS_INJECT_CONFIG` に指定する。
先頭の `~` はホームに展開する。
読むのはユーザースコープの `settings.json` だけで、プロジェクトスコープの `env` は読まない。
`ALIAS_INJECT_CONFIG` が無いときは、何も追加せずに入力をそのまま渡す。

置き場所の例は `~/.config/alias-inject/settings.yaml`。
入力の送信ごとに、設定ファイルと読むリポジトリの `dev-docs.yaml`、照合する YAML の更新時刻を確かめ、変わったものだけ読み直す。

## 最上位のキー

| キー | 中身 |
| --- | --- |
| `global` | 全てのプロジェクトで使う設定 |
| `projects` | プロジェクトごとの設定。`match` が当たった要素だけを `global` に重ねる |

## global のキー

<!-- table: data -->

| キー | 型 | 必須 | 既定値 | 説明 |
| --- | --- | --- | --- | --- |
| `enabled` | boolean | - | `true` | `false` のときは何も追加しない |
| `repositories` | object[] | - | なし | 読むリポジトリの `dev-docs.yaml`。キーは [repositories の要素のキー](#repositories-の要素のキー) |
| `aliases` | object[] | - | なし | 端末だけのエイリアス。キーは [aliases の要素のキー](#aliases-の要素のキー) |
| `origins` | `user` / `plugin` の並び | - | すべての出所 | 文脈を追加する入力の出所 |
| `max_items` | integer | - | `20` | 1 回に追加する語の上限。1 以上の整数で、それ以外の値は既定を使う |
| `max_chars` | integer | - | `4000` | 1 回に追加する文脈全体（見出しを含む）の文字数の上限。1 以上の整数で、それ以外の値は既定を使う |
| `exclude` | string の並び | - | なし | 照合しない語。入力・語と同じ正規化をしてから比べる |
| `heading` | string | - | `この発言に出る用語` | 追加する文脈の先頭に置く見出し |

<!-- /table -->

`origins` の値は次のとおり。
書かないとき、空の並びのとき、許す値が 1 つも無い並びのときは、すべての出所が対象になる。
それ以外の値は無視する。

| 値 | 対象の入力 |
| --- | --- |
| `user` | 利用者の入力。tmux から送る ai-monitor の指示を含む |
| `plugin` | プラグインが送信した入力 |

## repositories の要素のキー

| キー | 型 | 必須 | 既定値 | 説明 |
| --- | --- | --- | --- | --- |
| `config` | string | 必須 | - | 読むリポジトリの `dev-docs.yaml` のパス |
| `enabled` | boolean | - | `true` | `false` のときは、そのリポジトリを読まない |

- `config` の先頭の `~` はホームに展開する。相対パスは、`global` の中なら設定ファイルのフォルダから、`projects` の中なら起動したプロジェクトの直下から解決する
- `dev-docs.yaml` は `aliases` だけを読み、他のキーは読まない。`aliases` を持たない `dev-docs.yaml` は、定義が 0 件のリポジトリとして扱う
- 読めない `dev-docs.yaml` は、そのリポジトリの定義だけを照合から外す。読めなかったパスと理由は debug log に出る
- `dev-docs.yaml` の `aliases` の要素は、下の [aliases の要素のキー](#aliases-の要素のキー) と同じ構造で、`paths` の相対パスはその `dev-docs.yaml` のフォルダ（リポジトリの直下）から解決する

## aliases の要素のキー

端末の設定の `aliases` も、`dev-docs.yaml` の `aliases` も、同じ構造で記載する。
構造は [エイリアスのスキーマ](./エイリアスのスキーマ.md) の `aliases` の要素と同じ。

<!-- table: data -->

| キー | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `id` | string | 必須 | 要素の ID。1 つの設定の中で一意にする |
| `enabled` | boolean | - | `false` のときは、その要素を使わない。既定は `true` |
| `type` | `term` / `doc` / `command` / `url` | 必須 | 追加する列と書式を決める引用の種類 |
| `paths` | string の並び（1 件以上） | 必須 | 読む YAML のパスか glob。ファイルと glob を混ぜてよい |
| `fields` | object | 必須 | 引用に使う値を、読む YAML のどの列から取るかの対応。キーは [type ごとの fields](#type-ごとの-fields) |

<!-- /table -->

- スキーマ `schemas/aliases.schema.yaml` に合わない要素と、先の要素と `id` が重なる要素は、照合から外す。外した要素の出所・`id`・理由は debug log に出る
- `paths` の glob は、`*` がフォルダの区切りを除く任意の文字列、`**` が任意の深さのフォルダに当たる
- `paths` の先頭の `~` はホームに展開する。相対パスは、端末の設定の `global` の中なら設定ファイルのフォルダから、`projects` の中なら起動したプロジェクトの直下から、`dev-docs.yaml` の中ならそのフォルダから解決する
- `fields.match` の列の値が並びなら、要素ごとに照合する。文脈に出す語は `fields.title` の列の値で、`fields.title` が無いときは `fields.match` の最初の列の値になる
- `fields.avoid` はスキーマが受け付けるが、文脈には使わない

## type ごとの fields

`fields` の値は、読む YAML の列の名前で、`match` だけは列の名前の並び（1 件以上）。
表に無いキーは記載できない。

| type | 必須の fields | 任意の fields |
| --- | --- | --- |
| `term` | `id`・`match`・`description` | `title`・`related`・`avoid` |
| `doc` | `id`・`match`・`description` | `title` |
| `command` | `id`・`match`・`command` | `title`・`description`・`cwd` |
| `url` | `id`・`match`・`url` | `title`・`description` |

## type ごとに追加する列

追加する文脈には、どの `type` でも語と `id` を並べる。
続く列は `type` ごとに次のとおりで、値のあるものだけを並べる。
同じ `type` の要素の語は、リポジトリや `aliases` の要素が違っても 1 つのセクションにまとめる。

| type | セクションの見出し | 追加する列 | 用途 |
| --- | --- | --- | --- |
| `term` | `用語` | `description`・`related` | 用語。`related` は関連する文書の ID と名前 |
| `doc` | `文書` | `description` | 文書 |
| `command` | `コマンド` | `command`・`cwd`・`description` | コマンド |
| `url` | `URL` | `url`・`description` | URL |

## projects の要素のキー

| キー | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `match` | string | 必須 | 絶対パスかプロジェクト名 |
| `repositories` | object[] | - | `match` が当たったときに `global.repositories` の後ろへ重ねる読むリポジトリ |
| `aliases` | object[] | - | `match` が当たったときに `global.aliases` の後ろへ重ねるエイリアス |

`match` は次のときに当たる。

| 指定 | 当たるとき |
| --- | --- |
| 絶対パス | 起動したプロジェクトの直下が、そのパスかその配下 |
| プロジェクト名 | リポジトリのフォルダ名が一致する |

worktree は、本体のパスとフォルダ名で見る。

### 重ね方

`projects` の要素は、`global` と同じキーを持てる。
当たった要素を並びの順に `global` へ重ねる。
`repositories`・`aliases`・`exclude` は後ろに追加し、それ以外のキーは置き換える。
同じ `dev-docs.yaml` を `global` と `projects` の両方が指すときは 1 回だけ読み、`aliases` の `id` が先の要素と重なる要素は外す。
別のリポジトリや要素にある同じ語は、どちらも追加する。

## 設定の例

```yaml
global:
  repositories:
    - config: ~/repo/knowledge/dev-docs.yaml
  aliases:
    - id: glossary
      type: term
      paths:
        - ~/notes/term/*.yaml
      fields:
        id: id
        match: [name, aliases]
        description: description
        related: related
  max_items: 20
  max_chars: 4000
  exclude: [それ]
projects:
  - match: sample
    aliases:
      - id: commands
        type: command
        paths:
          - docs/command/*.yaml
        fields:
          id: id
          match: [name]
          command: command
          description: description
```
