## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 入力の照合 | `prompt.submit` で `e.text` を正規化（NFKC・英字の小文字・前後の空白の除去）し、語の一覧の各語を部分文字列として含むかで照合する | 正規表現は使わない。スラッシュコマンドの行は対象外 |
| 文脈の追加 | 当たった語のうち未記録の語を、`heading` の下にソースの `label` ごとのセクションで並べ、`next({ ...e, context: [...(e.context ?? []), 文脈] })` で渡す | 入力の文は変えない |
| 引用の種類 | `type`（term・doc・command・url）ごとに追加する列と書式を変える | 他の種類は後で追加できるよう、種類ごとの書式を 1 か所にまとめる |
| 上限 | `max_items` 語・`max_chars` 文字を超えた語はその回に追加せず、記録にも入れない | 次の入力で同じ語が出れば追加の対象になる |
| 出所 | `e.origin` が `origins` に無いときは追加しない | 出所の値の対応は PoC 検証で確かめる |
| 記録 | 追加した語をセッション ID ごとに `$.state` に持ち、圧縮の後と `/clear` でそのセッションの記録を消す | 記録の持ち方と消すイベントは PoC 検証で確かめる |
| 設定の読み込み | `ALIAS_INJECT_CONFIG` の YAML を読み、`global` に当たった `projects` を並びの順に重ねる | `~` の展開と `match` の当て方は knowledge の規約『claudeプラグイン』の `## 設定ファイル` |
| 読み直し | `turn.start` で設定ファイルと `files` の glob に当たる YAML の更新時刻を確かめ、変わったものだけ読み直す | glob に当たるファイルの増減も変更として扱う |
| 読めないとき | 読めない・書式の誤りは、そのソース（設定ファイルなら全体）を照合から外し、入力をそのまま渡す | 例外を外へ出さない |
| サンプル | 実値を入れない `settings.sample.yaml` をリポジトリの直下（プラグインの直下）に置く | 項目は `要件.md` の `### 設定` の表 |
| YAML の読み込み | mod のランタイムで YAML を読む | `未確定`（`要件.md` の `## 要望`。決める段: PoC 検証） |

### 非機能の観点

| カテゴリ | 方針 | 補足 |
| --- | --- | --- |
| 性能 | 入力の送信で増える待ち時間を、Claude Code が hooks モジュールの処理を待つ上限から決める | 非機能要件の「入力の送信で増える待ち時間」。照合のたびにファイルを読まず、読み込んだ語の一覧をメモリに持つ |
| 動作環境 | 非機能要件の対応 OS・対応する Claude Code のバージョンは変えない | PoC 検証で使うイベントが 2.1.310 以上で動くかを確かめる |
| セキュリティ | 設定と YAML は読むだけで、書き込みも外への送信もしない | - |

PoC 検証で確かめる核心機構は次のとおり。

| 観点 | 成功条件 |
| --- | --- |
| ファイルの読み込み | `$.fs` でプラグインの外の絶対パス（`~` を展開したもの）と、起動したプロジェクトからの相対パスのファイルを読め、更新時刻を取れる |
| glob | `files` の glob に当たるファイルの一覧を取れる |
| セッションの記録 | `$.state` にセッション ID ごとの値を持ち、同じセッションの次の `prompt.submit` で読める |
| 圧縮・`/clear` | 圧縮の後と `/clear` を mod のイベントで受け、記録を消せる |
| ターンの開始 | `turn.start` が `prompt.submit` より前に呼ばれる |
| 出所 | 利用者の入力・プラグインの入力・他のセッション（tmux から送った ai-monitor の指示）を `e.origin` で見分けられる |
| YAML の読み込み | mod のランタイムで YAML を読む手段がある |
