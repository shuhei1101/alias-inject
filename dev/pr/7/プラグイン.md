## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 入力の照合 | `prompt.submit` で `e.text` を正規化（NFKC・英字の小文字・前後の空白の除去）し、語の一覧の各語を部分文字列として含むかで照合する | 正規表現は使わない。スラッシュコマンドの行は対象外 |
| 文脈の追加 | 当たった語のうち未記録の語を、`heading` の下にソースの `label` ごとのセクションで並べ、`next({ ...e, context: [...(e.context ?? []), 文脈] })` で渡す | 入力の文は変えない |
| 引用の種類 | `type`（term・doc・command・url）ごとに追加する列と書式を変える | 他の種類は後で追加できるよう、種類ごとの書式を 1 か所にまとめる |
| 上限 | `max_items` 語・`max_chars` 文字を超えた語はその回に追加せず、記録にも入れない | 次の入力で同じ語が出れば追加の対象になる |
| 出所 | `e.origin` が `origins` に無いときは追加しない | 出所の値の対応は PoC 検証で確かめる |
| 記録 | 追加した語をセッション ID ごとに `$.state` に持ち、圧縮の後（`session.compact` の `next(e)` の後）と `/clear`（`session.end` の `reason: clear`）でそのセッションの記録を消す | 記録の持ち方と消すイベントは PoC 検証で確かめる |
| 設定の読み込み | ユーザースコープの settings の `env` の `ALIAS_INJECT_CONFIG` を `$.settings.read({ source: "user" })` で取り、指す YAML を読み、`global` に当たった `projects` を並びの順に重ねる | `~` は `$.env.get("HOME")` で展開する。`match` の当て方は knowledge の規約『claudeプラグイン』の `## 設定ファイル`。取り方は PoC 検証で確かめる |
| 読み直し | `prompt.submit` の中で照合の前に、設定ファイルと `files` の glob に当たる YAML の更新時刻（`$.fs.stat` の `mtimeMs`）とフォルダの一覧（`$.fs.list`）を確かめ、変わったものだけ読み直す | glob に当たるファイルの増減も変更として扱う。書き換えた直後の入力から反映される |
| 読めないとき | 読めない・書式の誤りは、そのソース（設定ファイルなら全体）を照合から外し、入力をそのまま渡す | 例外を外へ出さない |
| サンプル | 実値を入れない `settings.sample.yaml` をリポジトリの直下（プラグインの直下）に置く | 項目は `要件.md` の `### 設定` の表 |
| YAML の読み込み | YAML のパーサーをプラグインに同梱し、相対の import で読む | `未確定`（`要件.md` の `## 要望`。銘柄を決める段: ライブラリ選定） |

### 非機能の観点

| カテゴリ | 方針 | 補足 |
| --- | --- | --- |
| 性能 | 入力の送信で増える待ち時間は、外部の上限 `HookBudget.ms`（10,000ms。超えると hook が無かった扱いになる）と PoC 検証の実測を添えてユーザーへ回して決める | 非機能要件の「入力の送信で増える待ち時間」。照合のたびにファイルを読まず、読み込んだ語の一覧をメモリに持つ |
| 動作環境 | 非機能要件の対応 OS・対応する Claude Code のバージョンは変えない | PoC 検証で使うイベントが 2.1.310 以上で動くかを確かめる |
| セキュリティ | 設定と YAML は読むだけで、書き込みも外への送信もしない | - |

PoC 検証で確かめる核心機構は次のとおり。

| 観点 | 成功条件 |
| --- | --- |
| 設定ファイルの場所 | ユーザースコープの settings.json の `env` に置いた `ALIAS_INJECT_CONFIG` の値を、`$.env.get` と `$.settings.read({ source: "user" })` のそれぞれで取得できる（ログに値が出る）。`~` は `$.env.get("HOME")` で展開できる。両方で取れたときは、プロジェクトの settings に上書きされない `$.settings.read({ source: "user" })` を採る |
| ファイルの読み込み | `$.fs` でプラグインの外の絶対パスと、起動したプロジェクトからの相対パスのファイルを読め、更新時刻（`mtimeMs`）を取れる |
| glob | `files` の glob に当たるファイルの一覧を取れる。ランタイムに glob が無いときは、`$.fs.list` の一覧から照合して同じ一覧を作れる |
| 読み直し | 設定ファイルか用語の YAML を書き換えた直後の入力で、書き換え後の語の目印が `context` に入る。`prompt.submit` と `turn.start` の呼ばれた順はログに残すだけにする |
| セッションの記録 | `$.state` にセッション ID ごとの値を持ち、同じセッションの次の `prompt.submit` で読める |
| 圧縮 | `session.compact`（`trigger` が `manual` と `auto`）の `next(e)` の後で削除の処理が呼ばれたことがログに出て、次の入力で同じ語の目印がもう一度 `context` に入る。`precompute` では圧縮が起きないため削除の対象から外すかを記録する |
| `/clear` | `session.end`（`reason: clear`）で削除の処理が呼ばれたことがログに出て、次の入力で同じ語の目印がもう一度 `context` に入る。`/clear` の前後で `$.session.id()` が変わるか、`$.state` の値が残るかをログに出す |
| 出所 | 利用者の入力が `composer`、`$.prompt.submit` で送った入力が `plugin` になる。tmux の `send-keys` で送った入力（ai-monitor の指示）は端末への打鍵のため `composer` になると予測し、結果を記録する |
| YAML の読み込み | mod のランタイムで YAML を読む手段がある。無いときは「無い」と記録してライブラリ選定へ回す |
| 待ち時間 | 合否の閾値は置かず、照合を含む `prompt.submit` の処理時間の p50・p99.9 を、照合に使う想定の YAML（knowledge の `docs/term/` など）の実際の語数と、その 10 倍の語数で測って記録する |

検証構成は、一時の `CLAUDE_CONFIG_DIR` に検証用の `settings.json`（`env` に `ALIAS_INJECT_CONFIG`）を置き、tmux の対話のセッションを `claude --plugin-dir {PoC の worktree}` で起動する。
本番との違いは、ユーザースコープの設定フォルダが一時のフォルダであることと、マーケットプレイスから入れずに `--plugin-dir` で読むことの 2 点。

不成立の扱い:

- 設定ファイルの場所・ファイルの読み込み・読み直し・セッションの記録・圧縮・`/clear` のどれかが成り立たないときは不成立とし、要件の見直し案をユーザーへ回す
- tmux から送った入力が `composer` になり ai-monitor の指示を見分けられないときは、`origins` から「他のセッション」を外すか、見分ける別の手掛かりを探すかの見直し案をユーザーへ回す
- 待ち時間は実測と `HookBudget.ms` を添えて、決定値をユーザーへ回す

結論は成立。
YAML の読み込みは案 A が成り立たないため、案 B のパーサーの銘柄をライブラリ選定で決める。
照合に使う想定の knowledge の `docs/term/` はまだ無いため、実際の語数は knowledge の develop にあるタグの語彙（`docs/tags.yaml` の 40 語）とルールの YAML（`docs/rule/` の 211 件）を足した 250 語とした。
`$.prompt.submit` は `prompt.submit` の中から呼ぶと「処理中のターンを待つことになる」として拒まれ、`turn.complete` から呼ぶと送れた。
`/compact`・`/clear` の行は `prompt.submit` に届かなかった。
3 回目の入力で Haiku は「なし」と返したが、セッションの記録には `hook_additional_context` の添付が残り、API へも送られていた。

核心のコード（設定と用語の読み直しと、文脈の追加）:

```ts
const stat = await $.fs.stat(path)
if (configCache === undefined || configCache.path !== path || configCache.mtimeMs !== stat.mtimeMs) {
  const doc = load(await $.fs.read(path)) as { global: { sources: { files: string }[] } }
  configCache = { path, mtimeMs: stat.mtimeMs, files: doc.global.sources.map(s => s.files) }
}
const files = (await Promise.all(configCache.files.map(f => expandGlob($, f)))).flat()
const all = (await Promise.all(files.map(f => loadTerms($, f)))).flatMap(c => c.terms)
const already = held.value?.[sessionId] ?? []
const hits = match(e.text, all).filter(t => !already.includes(t.id))
if (hits.length === 0) return next(e)
await $.state.set(injected, { ...(held.value ?? {}), [sessionId]: [...already, ...hits.map(h => h.id)] })
return next({ ...e, context: [...(e.context ?? []), `ALIAS-POC の文脈: ${hits.map(h => h.id).join(', ')}`] })
```

diff の見どころ:

- `poc/mod/hooks/register.tsx` の `session.compact` は `next(e)` の後で、`trigger` が `precompute` でないときだけ記録を消す
- `poc/mod/hooks/register.tsx` の `turn.complete` で `$.prompt.submit` を呼ぶ（`prompt.submit` の中からは呼べない）
