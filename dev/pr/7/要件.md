# 要件

## 要望

入力の送信（`prompt.submit`）ごとに、入力の文の語を設定ファイルで指定した YAML の用語・エイリアスと照合し、そのセッションで初めて出た語の引用の文脈を、入力の文を変えずにモデルにだけ追加する。

### 設定

- ユーザースコープの `~/.claude/settings.json` の `env` の `ALIAS_INJECT_CONFIG` が指す YAML を設定ファイルとして読む。値の先頭の `~` はホームに展開する。`ALIAS_INJECT_CONFIG` が無いときは何も追加しない
- 設定ファイルの最上位は `global` と `projects`。`projects` の要素は `match`（絶対パスかプロジェクト名）で当たったときだけ、並びの順に `global` へ重ねる（knowledge の規約『claudeプラグイン』の `## 設定ファイル`）
- 外に出す項目は次のとおり。正規化・1 セッション 1 回・記録の消去は固定で、設定にしない

  | 項目 | 中身 | 既定 |
  | --- | --- | --- |
  | `enabled` | 全体のオンオフ | true |
  | `sources[]` | `label`・`type`・`files`・`id`・`words`・`description`・`related`・`mcp`・種類ごとの列（`command`・`cwd`・`url`） | なし |
  | `origins` | 対象にする入力の出所（利用者・プラグイン・他のセッション） | すべて |
  | `max_items` | 1 回に追加する語の上限 | 20 |
  | `max_chars` | 1 回に追加する文脈の文字数の上限 | 4,000 |
  | `exclude` | 照合しない語 | なし |
  | `heading` | 文脈の先頭の見出し | この発言に出る用語 |

- `files` は YAML の glob。`projects` の中の相対パスは、起動したプロジェクトの直下から解決する
- 実値を入れないサンプル `settings.sample.yaml` をプラグインの中に置く

### 照合

- 照合するのは `words` に挙げた列の値（用語とエイリアス）だけ。値が並びなら要素ごとに照合する
- 照合の前に、入力と語の両方を NFKC・英字の小文字・前後の空白の除去でそろえる。正規表現は使わない
- `exclude` に挙げた語は照合しない
- 当たったスコープ（`global` と当たった `projects`）の全ソースを照合し、別のソースの同じ語は両方とも追加する

### 文脈の追加

- `type` ごとに追加する列を変える

  | type | 追加する列 |
  | --- | --- |
  | term | 語・`id`・`description`・`related`（関連する文書の ID と名前） |
  | doc | 語・`id`・`description`・`mcp` |
  | command | 語・`id`・`command`・`cwd`・`description` |
  | url | 語・`id`・`url`・`description` |

- 文脈は `heading` の見出しの下に、ソースの `label` ごとのセクションに分けて並べる
- 1 回に追加するのは `max_items` 語・`max_chars` 文字まで。超えた語はその回に追加せず、記録にも入れない
- 追加した語はセッション ID に紐づけて記録し、同じセッションで二度目に出ても追加しない
- 圧縮の後（PostCompact）と `/clear` で、そのセッションの記録を消す
- 入力の出所が `origins` に無いときは何も追加しない。既定ではすべての出所（ai-monitor が送る指示を含む）が対象
- 入力の文はそのまま渡す。スラッシュコマンドの行は対象外

### 読み直しと読めないとき

- 入力の送信ごとに、照合の前に設定ファイルと照合する YAML の更新時刻を確かめ、変わっていれば読み直す（D-71 のターンの開始は、入力の送信より後に呼ばれるため、書き換えた直後の入力に間に合わない）
- 設定ファイル・YAML が読めない・書式が誤っているときは、そのソース（設定ファイルが読めないときは全体）の文脈を追加せず、入力をそのまま渡す。入力の送信は止めない

`未確定`: mod のランタイムで YAML を読む手段（決める段: PoC 検証、無ければライブラリ選定）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | mod のランタイムが持つ YAML の読み込みを使う | 依存を持ち込まない | ランタイムに有るかは未確認 |
| B | YAML のパーサーのパッケージを同梱する | 確実に読める | mod に外部のパッケージを入れる手段を確かめる必要がある |

推奨: A

有れば依存を増やさずに済む。無いと分かった時点で B をライブラリ選定へ回す。

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| skill・tool・path・env・avoid の引用の種類 | D-91 で最初は term・doc・command・url の 4 種類だけを作ると決めた。今回の `type` の仕組みの上に追加する | 起票予定 |
| 画面に出す発言の語のマーカー | D-64 で画面の表示は mdmark-style が受け持つと決めた | mdmark#116 |
| 照合の誤一致を減らす仕組み（最短の文字数など） | D-68 で追加しないと決めた。誤一致は `exclude` で避ける | 予定なし |
| 利用者の手元の `~/.claude/settings.json` の `env` と `~/.config/alias-inject/settings.yaml` の用意 | 利用者の環境の設定で、照合する YAML（knowledge の `docs/term/` など）の置き場所も利用者が決める。今の判断はスコープ外で、手順は `docs/使い方/セットアップ.md` に書く。反映作業に含めるかはレビューで確定する | 予定なし |
