# 要件

## 要望

release PR #17 の E2E で fail した 2 件のテスト不備を修正し、`hooks/` の処理は変えない。

| Issue | 終わりの条件 |
| --- | --- |
| #22 | `tests/e2e/support/harness.py` の `ClaudeSession._drain` が、改行で終わっていない末尾の要素（書きかけの行）と末尾の空の要素を `consumed` に数えない。#22 の表の 5 件（`test_session_flow.py` の `test_normal`・`test_prompt_context.py` の `test_normal_when_over_limit`・`test_reload.py` の 3 件）が時間切れにならずに pass する |
| #23 | `test_error_when_values_unavailable` の準備で、hooks モジュールの子プロセスから `env` を確実に起動できない状態を作り（Claude Code が子プロセスへ渡す PATH の決まり方を確かめてから仕込みを変える）、このテストが pass する |

- #22: 2 回の読み取りの間に追記された行を、改行で終わった行から順に全て返す（1 回目に `{"n":1}\n` を読み、2 行を追記した 2 回目に `{"n":2}` と `{"n":3}` の両方が返る）
- #23: 仕込みを変えた後も、同じファイルの正常シナリオ 4 件が pass する

`未確定`: `env` を起動できない状態の作り方（決める工程: PoC 検証）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | Claude Code が `$.process.run` の子プロセスへ渡す PATH の出所を確かめ、その出所から `env` を外す | シナリオの「子プロセスを起動できない」（`catch` の経路）をそのまま確かめられる | 出所によっては `harness.py` に新しい仕込みが要る |
| B | 子プロセスへ届く PATH の先頭に、終了コード 1 で終わる `env` を置く | PATH の出所に関わらず仕込める | 確かめる経路が「終了コードが 0 以外」に変わり、シナリオのフローとセットアップの記述を修正する |

推奨: A

異常シナリオのフローは子プロセスを起動できない経路を書いており、テストの仕込みをシナリオに合わせるのが Issue の終わりの条件にも沿うため。
