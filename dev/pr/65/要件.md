# 要件

## 要望

端末の設定（設定ファイル）のパスを、`~/.claude/settings.json` の `env` に `ALIAS_INJECT_CONFIG` を記載しなくても決められるようにする。

- `ALIAS_INJECT_CONFIG` が無いときは、既定のパス `${XDG_CONFIG_HOME:-~/.config}/alias-inject/settings.yaml` を参照する
- `ALIAS_INJECT_CONFIG` は、ユーザースコープの `settings.json` の `env` に加え、シェルの環境変数からも参照する
- ユーザースコープの `settings.json` の `env.ALIAS_INJECT_CONFIG` は今どおり参照する
- 既定のパスに設定ファイルが無いときは、今の `ALIAS_INJECT_CONFIG` が無いときと同じく、何も追加せずに入力をそのまま渡し、debug log を出さない
- `ALIAS_INJECT_CONFIG` が指すファイルが読めないときは、今どおり設定ファイルのパスと理由を debug log に出す

`未確定`: `ALIAS_INJECT_CONFIG` を参照する順（決める工程: 単一ユースケース設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | ユーザースコープの `settings.json` の `env` → シェルの環境変数 → 既定のパスの順 | 今 `settings.json` に記載している端末の動きが変わらない。`settings.json` の書き換えが次の入力から有効になる | シェルで一時的に上書きしても、`settings.json` に値があると有効にならない |
| B | シェルの環境変数 → ユーザースコープの `settings.json` の `env` → 既定のパスの順 | その実行だけ環境変数で上書きできる | Claude Code は `settings.json` の `env` をプロセスの環境変数にも入れるため、プロジェクトスコープの `env` の値を取得する |

推奨: A

`#7` の PoC で、プロジェクトスコープの settings に上書きされない `$.settings.read({ source: "user" })` を採った理由を保てる（`## 変更箇所の由来`）。

端末の設定を作るスキル `global-setup` をプラグインに追加する。
流れは Issue の `## 決まったこと` の global-setup の流れに沿う。

1. 端末の設定のパスを決める（`ALIAS_INJECT_CONFIG` があればその値、無ければ既定のパス）
2. 端末の設定があれば、旧い構造（`type`・`fields`、`metadata.alias_type`）の行が残っていないかを確認し、残っていれば『設定の移し替え』の手順で移す。無ければ `settings.sample.yaml` を元に、利用者に聞いた読むリポジトリの `dev-docs.yaml` と用語集の YAML のパスを記載して作る
3. 端末の設定のパスが既定のパスと違えば、`${CLAUDE_CONFIG_DIR:-~/.claude}/settings.json` の `env` に `ALIAS_INJECT_CONFIG` を記載する（`env` のほかのキーとファイルのほかの内容は変えない）
4. フックが動くこと（試しの入力で引用の文脈が追加されること）を確認し、動かなければ debug log の場所と直し方を示して止まる
5. 作ったもの・`env` に記載したキー・確認した結果を示す

`未確定`: フックが動くことの確かめ方（決める工程: 単一ユースケース設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `claude -p` に、端末の設定の用語を含む文を指定し、回答に用語の説明が反映されるかを確認する | 利用者の操作が要らない | 実行のたびにモデルの利用量がかかる |
| B | スキルを実行したセッションで、利用者に用語を含む文の入力を頼み、回答を見て判定する | 利用量が追加でかからない | 利用者の操作が要る。スキルの手順が入力の待ちで途切れる |

推奨: A

`global-setup` は端末ごとに 1 回の実行で、利用量は 1 回分に収まる。

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| `ALIAS_INJECT_PORT`・`ALIAS_INJECT_STATE_DIR` | alias-inject は MCP のサーバーを持たず、記録は Claude Code の `$.state` に配置するため、ポートと状態の置き場を持たない | 予定なし |
| リポジトリごとの `setup` のスキル | Issue の決定のとおり、読むリポジトリは端末の設定の `repositories` に追加するため、リポジトリごとの登録が要らない | 予定なし |
| knowledge の判定フローチャート『設定値の置き場所』と規約への、既定のパスと環境変数の名前の付け方の記載 | knowledge のリポジトリの変更で、同じ決定の Issue を knowledge に起票済み | 予定なし |
