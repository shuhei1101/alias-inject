## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| `tool.call` の入力の確認 | 型の宣言（`.claude-plugin/types/claude-code/index.d.ts` の `ToolCallInput`・`AgentLoop`、`claude-code-tools/index.d.ts` の `Read`）にあるツールの名前・Read の `file_path`・MCP の引数・`agentId` が、実行時の `e` に入るかを PoC で裏取りする | 読めない値があれば、その論点の方針をインターフェース定義設計で決め直す |
| 並列の呼び出し | 並列に呼んだ 2 つのツールの `tool.call` が同時に走るかを PoC で確かめる | 同時に走る場合、記録の追加を `$.state.set` の `ifVersion` で書き直す方針をインターフェース定義設計へ渡す |
| 照合の共通化 | `selectContext` の設定と語の読み込みを、`prompt.submit` と `tool.call` で共有する関数に分ける | 出所（`origins`）の判定は `prompt.submit` だけに残す |
| ツールの結果の照合 | `handleToolCall` で `result.text` に `findHits` をかけ、選んだ文脈と変数参照の値の行を `context` の末尾に並べて返す | 照合と変数参照のどちらかが失敗しても、もう一方の結果とツールの結果は返す |
| 照合から外すツール | 設定ファイルにツールの名前の並びを追加し、当たるツールの結果は照合しない | キーは `exclude_tools`。`projects[]` では後ろに追加する |
| 自分自身の文書 | Read の `file_path` が語の指す文書のパス、MCP の引数の文書の ID が語の ID に当たる語を、当たった語から外す | - |
| 出た回数の多い順 | `findHits` が語ごとに本文に出た回数を返し、ツールの結果では回数の降順に並べてから `selectEntries` で上限まで選ぶ | メッセージの照合には当てない |
| サブエージェントの記録 | 記録のキーを、メインの会話はセッションの ID、サブエージェントはセッションの ID と `agentId` の組にする | サブエージェントの圧縮でその `agentId` の記録だけを消す。`/clear` では消さない。ワークフローのエージェント・エンジンのフォーク（圧縮・メモリ）も `agentId` があればサブエージェントと同じに扱う |
| 既存機能への影響 | メッセージの照合の結果は今と変わらない | 既存の単体・結合・E2E を回す |
| 性能 | ツールの結果の照合で増える待ち時間を非機能要件に追加し、非機能要件テストで測る | 200ms（入力の送信と同じ） |

成立。
`tool.call` の `e` には型の宣言どおり、ツールの名前（`tool`）・呼び出しの ID（`tool_use_id`）・ツールの引数（直下に展開）が入り、`agentId` はサブエージェントの中の呼び出しにだけ入った。
`context` に並べた 2 つの文字列は、どのツールでも結果の後ろの文脈としてモデルに届いた。
並列に呼んだ Read 2 つの `tool.call` は 1 回の観測では順に走ったが、同時に走らないことの保証は型の宣言にも無いため、記録の追加を `ifVersion` で書く方針をインターフェース定義設計へ渡す。

最小再現コードの要点（[poc/tool-call-input/hooks/register.ts](https://github.com/shuhei1101/alias-inject/blob/dbedf5aa391f7ce1e7c9e40b0e698bfe06eabedf/poc/tool-call-input/hooks/register.ts)。記録は [poc/tool-call-input/result/](https://github.com/shuhei1101/alias-inject/blob/dbedf5aa391f7ce1e7c9e40b0e698bfe06eabedf/poc/tool-call-input/result)）:

```ts
on('tool.call', async ($, e, next) => {
  const dir = await $.env.get('POC_LOG_DIR')
  const id = e.tool_use_id
  const enteredAt = Date.now()
  const r = await next(e)
  const leftAt = Date.now()
  // 並列の呼び出しで書き込みが競合しないよう、1 呼び出し 1 ファイル
  if (dir !== undefined) await $.fs.write(`${dir}/${id}.json`, JSON.stringify({ enteredAt, leftAt, e }))
  if (r.deny !== undefined || r.isError || typeof r.text !== 'string') return r
  return { ...r, context: [...(r.context ?? []), `POC-MARK-QUOTE-${id.slice(-6)}`, `POC-MARK-VAR-${id.slice(-6)}`] }
})
```

diff の見どころは、入口と `next(e)` の後の時刻を 1 呼び出し 1 ファイルで残して区間の重なりを後から比べる点と、`context` に 2 つの要素を並べて返す点。
