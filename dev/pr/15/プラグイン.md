## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| イベントの受け取り | `tool.call` に処理を登録し、`next(e)` が返したツールの結果の `text` から `!{名前}` を拾う | Read・Bash・MCP のツールの結果を同じ処理で扱う。エラーの結果・`deny` は扱わない |
| 名前の拾い出し | `!{[A-Za-z_][A-Za-z0-9_]*}` に当たる名前を出現順に、重なりを除いて集める | 変数参照が無ければ子プロセスを起こさず結果をそのまま返す |
| 値の取得 | `$.process.run(["env", "-0"])` の 1 回の子プロセスで環境全体を NUL 区切りで受け、集めた名前の値を引く。出てこない名前は設定されていない名前とする | `$.env.get` は名前を文字列リテラルでしか受けないため。`env` は対応 OS（Linux）の coreutils にあり、依存を増やさない |
| 文脈の組み立て | 名前ごとに `変数参照の値: !{名前} = {値}` の 1 行を作り、設定されていない名前は設定されていないことを添えた 1 行にする。結果の `context` の末尾に追加する | 他のフックが追加した `context` は残す |
| 失敗の扱い | 子プロセスが 0 以外の終了コードで終わったとき・起動できないとき・待ちの上限を超えたとき・想定しない例外のときは、debug log に出し、文脈を追加せずツールの結果をそのまま返す | 入力への引用の文脈の追加と同じ扱い。`$.process.run` は 0 以外の終了コードでは例外にならない |
| 既存機能への影響 | `prompt.submit`・`session.compact`・`session.end` の処理と設定ファイルのキーは変えない | - |

成立。
`tool.call` の `next(e)` が返す結果の `text` は、組み込みのツールと MCP のツールのどちらでも読め、返り値の `context` の末尾に追加した文字列はツールの結果の後ろの文脈としてモデルに届いた。
`$.process.run(["env", "-0"])` の子プロセスは Claude Code の環境変数を継いでおり、名前を文字列リテラルで書かずに値を引けた。
MCP のツールのうち ai-monitor の `read_docs_pages` は、自分で `!{名前}` を展開し、引けない名前があるとページを返さない（`変数参照を解決できません`）。この挙動は alias-inject の外で、`tool.call` で受けた結果に本文が無ければ文脈を追加しない扱いで足りる。

最小再現コードの要点（[poc/tool-call-context/hooks/register.ts](https://github.com/shuhei1101/alias-inject/blob/0a72f27b7ca3ddd9cfa00f670dfabfa6c681272b/poc/tool-call-context/hooks/register.ts)）:

```ts
on('tool.call', async ($, e, next) => {
  const r = await next(e)
  if (r.deny !== undefined || r.isError || typeof r.text !== 'string') return r
  const names = [...new Set([...r.text.matchAll(/!\{([A-Za-z_][A-Za-z0-9_]*)\}/g)].map((m) => m[1]))]
  if (names.length === 0) return r
  try {
    const run = await $.process.run(['env', '-0'])
    if (run.exitCode !== 0) return r
    const values = parseEnv(run.stdout) // NUL で区切り、最初の = で名前と値に分ける
    const lines = names.map((name) => {
      const value = values.get(name)
      return value === undefined ? `変数参照の値: !{${name}} は環境変数が設定されていない` : `変数参照の値: !{${name}} = ${JSON.stringify(value)}`
    })
    return { ...r, context: [...(r.context ?? []), lines.join('\n')] }
  } catch (error) {
    return r // 起動できない・timeoutMs の超過は例外になる
  }
})
```

diff の見どころは、`next(e)` の結果をそのまま広げて `context` だけを足す返し方（`ref` を残すため core のメッセージがそのまま使われ、本文は変わらない）と、`exitCode` を見る分岐と `catch` の分岐が別の失敗を受けている点。
