# 要件

## 要望

エイリアスの元の行のスキーマ（SSOT）を、dev-docs の documents の行の新しい構造（shuhei1101/dev-docs#32）に揃える（D-171。整理は A-25・A-26・A-36）。

- 引用の種類 `alias_type` を、`metadata` から行の属性 `alias_type` に移す。値は term・doc・command・url・skill・tool・path・env・avoid の 9 つ
- `metadata` の各キーの値を、値を取る文書の列名の文字列にする（`aliases: keywords`）。`{type: ref, field: ...}`・`{type: custom, value: ...}` の判別子つきのオブジェクトをなくす
- `metadata` に書かないキーは、同じ名前の列から取る。入れ子の列は `meta.summary` のように `.` でつなぐ
- スキーマの説明・例から行の `type` をなくす
- 端末の設定（`global.aliases`・`projects[].aliases`）の行は `alias_type` を必須にする。`dev-docs.yaml` の documents の行は、`alias_type` を持つ行だけを照合の定義として読む
- 旧い構造の行（`metadata.alias_type` を持つ行・`metadata` の値がオブジェクトの行）は照合に使わず、外した理由を debug log に出す
- 照合する語（`name` と `aliases`）・文脈に出す語（`name`）・種類ごとの必須のキー・追加する文脈の書式は変えない
- 端末の設定と dev-docs.yaml を、今の構造から新しい構造へ移し替える手順を公開ドキュメントに置く

alias-inject の `dev-docs.yaml` を新しい構造にする。

- `type: markdown` の行と `defaults[]` をやめる。Markdown は管理用の YAML（`files.yaml`）に 1 ファイル 1 行で載せ、`records: files`・`body_file: path` の行で読む。今 `defaults[]`・`custom` で付けているファイルごとのタグは、その行の `tags` に書く
- YAML の設計書の行の `type: yaml` と `tags: {type: custom}`（`scope:設計書`・`topic:シナリオ` など）をやめる。種類は `kind` で絞る
- YAML の設計書の行の `defaults[]` で付けている topic のタグは外す（設計書の `tags` の列へは書かない。#39）
- `name: {type: ref, field: title}` を `name: title` にする

新しい構造のスキーマを含むリリースのタグは、Sprint の release を master へ入れるときに打つ。
mdmark・dev-docs はそのタグを指定して取り込む（D-120）。

`records` の行で `name` が空の文書は、行の `body_file` が指す列の値のファイル名（拡張子を除く）、それも空なら `id` を名前にする（D-166・A-36 と同じ）。
エイリアスの元の行のキーに `body_file` を加える。
`files.yaml` の要素は `id` を持たないため、`files.yaml` を読む行は `metadata.id: path` を書いて `path` の列を id にする。

alias-inject の Markdown は `docs/files.yaml` 1 つに `docs/` の Markdown を載せ、行の `schema` は dev-docs の `templates/files.schema.yaml` を `dev/テンプレート/files.schema.yaml` にコピーして指す。

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| dev-docs がこのスキーマのタグを指定して取り込む | 取り込む側のリポジトリの作業で、この PR のスキーマとタグを前提にする | shuhei1101/dev-docs#32 |
| mdmark がこのスキーマのタグを指定して取り込む | 取り込む側のリポジトリの作業で、この PR のスキーマとタグを前提にする | 起票予定 |
| 設計書の `tags` 列へ、`defaults[]` で付けていた topic のタグを書く | 配布される設計書のテンプレートに `tags` の列が無い（ユーザーが案 A を選んだ） | #39 |
| `dev-docs.yaml` の否定の glob（`[!R]*.md`・`[!i]*.yaml`）を `exclude[]` へ書き換える | 同じ `dev-docs.yaml` を変えるが、目的が別の作業 | #38 |
| 今の構造（`metadata.alias_type`・判別子つきの値）の読み込みの互換 | Issue の要望で、旧い構造は読まない（破壊的変更）。移し替えの手順で代える | 予定なし |
| `metadata` の共通のキー（`tags`・`status`）を照合・文脈に使う | 検索と画面のための dev-docs のキーで、引用の文脈には要らない | 予定なし |
