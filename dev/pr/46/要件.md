# 要件

## 要望

AI Monitor `v0.3.0` の配布物のうち、alias-inject に有るものを `v0.3.0` に揃える。

| 分類 | 終わりの条件 |
| --- | --- |
| サイトのレイアウト | `python -m ai_monitor.distribution import-site --version v0.3.0` で `docs/_theme/` を取り込み、直下の控え `ai-monitor-theme.yaml` の版が `v0.3.0` になっている |
| テンプレート | `python -m ai_monitor.design_docs convert --from v0.2.0 --to v0.3.0` を流した後、設計書の検証のコマンド（`design_docs validate`）が `dev/設計書/` でエラーを出さない（`dev/テンプレート/` の各 Schema は `v0.3.0` と一致し、`v0.3.0` までの変換は無いため、設計書の差分は出ない見込み） |
| 追従のバージョン | [ai-monitor-version.ini](https://github.com/shuhei1101/alias-inject/blob/develop/ai-monitor-version.ini) が `v0.3.0` になっている |

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| 配信設定（`docs/_config.yml` のキーの追加） | alias-inject は `docs/_config.yml` を持たない | 予定なし |
| ルール索引（配布元の `rules.global.yaml` で増えた行の追加） | `rules.global.yaml` は監視対象プロジェクトからも直接参照する索引で、alias-inject の [rules.yaml](https://github.com/shuhei1101/alias-inject/blob/develop/rules.yaml) に追加する行は無い | 予定なし |
| プラグイン（MCP `update_plugins` での取り直し） | alias-inject のリポジトリの変更ではなく、稼働しているブランチへ入ったプラグインの変更はモニターが自動で効かせる（テンプレート『PRドキュメント/反映作業』の `時期`） | 予定なし |
| 設定スキーマ・MCP ツール（`settings.yaml` のキーの追加と `agents[].mcp_tools` の見直し） | alias-inject は `settings.yaml` を持たない（`settings.sample.yaml` はプラグインの設定ファイルの見本で、AI Monitor の設定とは別物） | 予定なし |
| 規約・外部規約・フェーズ手順・判定・観点の読み直し | alias-inject はこれらのコピーを持たず、エージェントは AI Monitor の develop（`v0.3.0` より新しい）のページを実行時に読んで作業している。成果物の書式は `dev/テンプレート/` の Schema（`v0.3.0` と一致）が決める | 予定なし |
| `dev/テンプレート/` の Schema 以外の差分（`README.md`・`index.yaml`・`index.schema.yaml`・`files.schema.yaml`） | alias-inject が持つのは自分の設計書の Schema だけで、目次と `files.schema.yaml` は alias-inject 固有の内容 | 予定なし |
| テンプレートの tags 列への topic のタグ | `v0.3.0` のテンプレートにはまだ `tags` の列が無く、この PR で前提は満たされない | #39 |
