# 要件

## 要望

文書ごとに、引用の文脈を追加する条件（照合条件）を AND・OR・NOT で記載できるようにする。
文書の `name`・`aliases` のどれかが当たり、かつ照合条件にも当たったときだけ、その文書の引用の文脈を追加する。

- 照合条件は文書ごとに 1 つ持つ。エイリアスごとには持たない
- 照合条件を持たない文書は、今と同じく `name`・`aliases` が当たれば追加する
- メッセージの照合（`prompt.submit`）とツールの結果の照合（`tool.call`）の両方に当てる
- 照合条件は文書の列に記載し、エイリアスの元の行の `metadata` で値を取る列の名前を指せる（他のエイリアスのキーと同じく、書かないときは同じ名前の列から取る）
- 照合条件の構造は dev-docs の `filter` と同じにする（条件: `field`・`op`・`values`・`match`、束: `and`・`or`・`not`）

  | 決まり | 内容 |
  | --- | --- |
  | 否定の書き方 | 1 つの条件の否定は否定の比べ方（`not_contains` など）、束の否定は `not` |
  | 入れ子の深さ | 3 レイヤーまで |
  | 値の正規化 | NFKC と大文字小文字を統一して比べる（`case_sensitive` で解除） |
  | 空の束 | 検査で弾く |
  | 省略形 | 条件を 1 つだけ記載するときは束で包まない |

照合条件のキーの名前は `inject_when` にする（インターフェース定義設計で決定）。

照合条件で比べる対象は、照合した本文（メッセージの文か、ツールの結果の本文）にする（単一ユースケース設計で決定）。

条件の `field` は必須のまま残し、値は照合した本文を指す `text` だけを許す（インターフェース定義設計で決定）。

比べ方（`op`）は `contains` とその否定の `not_contains` だけにする（インターフェース定義設計で決定）。

照合条件が誤っている文書（構造の誤り・4 レイヤー以上の入れ子・空の束）は照合から外し、理由を debug log に出す（インターフェース定義設計で決定）。

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| エイリアスごとの照合条件 | 文書ごとに 1 つ持たせると Issue の `## 決定` で決め、`aliases` の型を変えない | 予定なし |
| rule-inject・dev-docs への照合条件 | alias-inject にだけ入れると Issue の `## 決定` で決めた | 予定なし |
| knowledge の判定フローチャート・規約への照合条件の付け方 | 付け方の検討事項が未決定で、alias-inject の変更ではない。Issue の `## 依存・後続` のとおり、決まったら起票する | 起票予定 |
| [docs/使い方/エイリアスを登録するかを決める.md](https://github.com/shuhei1101/alias-inject/blob/develop/docs/%E4%BD%BF%E3%81%84%E6%96%B9/%E3%82%A8%E3%82%A4%E3%83%AA%E3%82%A2%E3%82%B9%E3%82%92%E7%99%BB%E9%8C%B2%E3%81%99%E3%82%8B%E3%81%8B%E3%82%92%E6%B1%BA%E3%82%81%E3%82%8B.md) への照合条件の分岐の追加 | 照合条件を付けるかの判定は、knowledge の判定フローチャートと同じ検討事項で決まり、今回の照合条件の追加が前提になる | 起票予定 |
| knowledge の『フォルダ構成』（`react-core-folder-structure`）など、既存の文書への照合条件の記載 | 配信元の文書の変更で、今回の照合条件の追加が前提になる | 起票予定 |
