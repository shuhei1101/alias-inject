# 要件

## 要望

モジュール構成の設計書のうち、要素の `container` が 2 つ以上の物理ファイルにまたがる 3 つを物理ファイルごとの設計書に分け、`design_docs validate` が `物理ファイルが 2 つ以上あります` のエラーを 1 件も出さない状態にする。

| 分ける設計書 | 物理ファイルごとに持たせる要素 |
| --- | --- |
| `プラグイン/スキーマ.yaml` | `hooks/lib/schema.ts`（`SchemaError`・`VALIDATION_KEYWORDS`・`ANNOTATION_KEYWORDS`・`loadAliasSchema`・`checkKeywords`・`validateSchema`）<br>`hooks/lib/aliases-schema.ts`（`ALIAS_SCHEMA`）<br>`scripts/gen-aliases-schema.mjs`（`generateAliasSchema`） |
| `プラグイン/入口.yaml` | `hooks/register.tsx`（`register`）<br>`hooks/handlers.ts`（`handlePromptSubmit`・`handleSessionCompact`・`handleSessionEnd`・`handleToolCall`） |
| `プラグイン/記録.yaml` | `types/index.d.ts`（`PluginState`）<br>`hooks/lib/record.ts`（`readRecorded`・`addRecorded`・`clearRecorded`） |

- 分けた後の設計書の `test_files` は、その物理ファイルの単体テストのファイル 1 つだけを持つ（単体テストの無い物理ファイルは持たない）
- 分けた要素を指す参照（`callees`・`refs`）を、分けた先の設計書へ付け替える
- `プラグイン/index.yaml` の目次に分けた先の設計書の行を追加し、README を生成し直す
- 要素の中身（引数・処理・単体テスト）は変えない

`未確定`: 分けた先の設計書の置き場所と名前（決める段: モジュール構成設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 今の `モジュール構成/プラグイン/{分類}.yaml` の並びに揃え、2 つ目以降の物理ファイルを同じフォルダの新しい分類の設計書にする（例 `生成したスキーマ.yaml`・`スキーマの生成.yaml`・`イベントの処理.yaml`・`状態の型.yaml`） | 他の 8 つの設計書と置き方が揃う | Schema の置き場所 `モジュール構成/{container}.yaml` とは揃わないまま |
| B | 分ける 3 つだけ Schema の置き場所 `モジュール構成/{container}.yaml` に置く | 分けた設計書は Schema の置き場所に揃う | 同じサブシステムの設計書の置き方が 2 通りになる |

推奨: A

置き場所を Schema に揃えるかは全ての設計書をまとめて決める事柄で、3 つだけ揃えると置き方が混ざるため。

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| 他の 8 つのモジュール構成の設計書（`読み込み.yaml` 等）を Schema の置き場所 `モジュール構成/{container}.yaml` へ移すこと | 検証はエラーを出さず、今回のエラーの原因は 1 つの設計書に物理ファイルが 2 つ以上あること。Schema の置き場所との違いを是正の対象にするかは判断が分かれるため、今の判断（対応しない）をレビューで確定する | 予定なし |
| `design_docs validate` が [dev/pr/21/反映作業/index.yaml](https://github.com/shuhei1101/alias-inject/blob/develop/dev/pr/21/%E5%8F%8D%E6%98%A0%E4%BD%9C%E6%A5%AD/index.yaml) と [dev/pr/41/反映作業/index.yaml](https://github.com/shuhei1101/alias-inject/blob/develop/dev/pr/41/%E5%8F%8D%E6%98%A0%E4%BD%9C%E6%A5%AD/index.yaml) へ出す目次の Schema のエラー（`items`・`summary` が無い） | 2 つはテンプレート『PRドキュメント/反映作業』の書式どおりで、検証が反映作業の一覧を目次の Schema で読むことが原因（AI Monitor 側の不具合） | [shuhei1101/ai-monitor#2704](https://github.com/shuhei1101/ai-monitor/issues/2704) |
