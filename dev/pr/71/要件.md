# 要件

## 要望

`dev/` を廃止し、文書を `docs/` と `schemas/` へ移す。
構成は [shuhei1101/ai-monitor#3307](https://github.com/shuhei1101/ai-monitor/pull/3307) の [dev/pr/3307/モニター.md](https://github.com/shuhei1101/ai-monitor/blob/cc97586e6966658ead68a3642c23dcf16b01e613/dev/pr/3307/%E3%83%A2%E3%83%8B%E3%82%BF%E3%83%BC.md) の `### 種類のフォルダ` と `### 置き場所の規則` に統一する。
ファイル名の ID・目次・`dev-docs.yaml` の行の構造は、同じ移行をマージ済みの [shuhei1101/project-index#13](https://github.com/shuhei1101/project-index/pull/13) に統一する。

終わりの条件:

- `dev/` の下に、この PR の PR ドキュメント `dev/pr/71/` のほかのファイルが残っていない。マージ済みの PR の PR ドキュメント（`dev/pr/5/` 〜 `dev/pr/69/`）は中身を変えずに `docs/pr/` へ移す
- `docs/` の下は種類のフォルダ（`architecture`・`nonfunctional`・`scenario`・`interface`・`module`・`config`・`test-procedure`・`dev-command`・`library`・`guide`）と、束のフォルダ `pr/`・`_` で始まる Pages の共通レイアウトだけで、種類のフォルダの中にフォルダが無い
- 中身の無い目次だけのフォルダ（`dev/設計書/ER図/`・`dev/設計書/外部API/`・`dev/エージェント運用/` の下・`dev/コーディング規約/`）は、種類のフォルダを作らずに削除する
- YAML の設計書のファイル名が `{ID}.yaml` になり、ID は種類の略号と連番（例: `ARCH-1`・`MOD-1`）になっている
- 設計書の中の、他の設計書を指す `dev/設計書/...` のパスが、移した後の置き場所を指している
- Schema が `schemas/{kind}.schema.yaml`（`common`・`index`・`files`・`phase` を含む）にあり、既存の `schemas/aliases.schema.yaml` は変わらない
- 共通の Schema の `visibility` の値が `public` / `internal` になり、全ての文書がメタデータ `visibility` を持ち、今の `docs/` の下の文書は `public`、`dev/` から移した文書は `internal` になっている
- `docs/はじめに/`・`docs/使い方/`・`docs/リファレンス/` の Markdown が `docs/guide/` にあり、分類はメタデータ `category`（`docs/guide/files.yml` の行）で持つ。サブフォルダにあったものは `{サブフォルダ}-{ファイル名}`（例: `コアコンセプト-引用の文脈.md`）にする
- 分類のトップページ `docs/guide/{分類}.md` があり、上タブ `docs/_theme/_data/nav.project.yml` を分類から作っている
- `docs/_config.yml` の `exclude` に、`internal` の文書だけを持つ種類のフォルダと `pr/`・`mock/`・`generated/` が載っている
- `CLAUDE.md`・`README.md`・`rules.yaml`・`dev-docs.yaml`・`.gitignore`・`skills/`・テスト・コードに、移す前のパスを指す記述が残っていない（この PR の PR ドキュメント `dev/pr/71/` と、`docs/guide/変更履歴.md` のタグで固定したリンクを除く）
- `dev-docs.yaml` の `paths` で、移す前と同じ件数の YAML の設計書を検索できる
- `dev-docs.yaml` の `docs/guide/files.yml` を参照する文書の行で、`docs/guide/` の Markdown を `visibility`・`category` つきで検索できる
- 移した後の作業ツリーで `python -m ai_monitor.design_docs validate --root {作業ツリーの直下}` を実行し、移し替えが原因の誤りが無い

この PR の PR ドキュメント `dev/pr/71/` は移さない。
稼働中のモニターは ai-monitor#3307 のマージまで `dev/pr/` を参照し、`docs/pr/71/` への移動は #3307 の反映作業『open の作業 PR の PR ドキュメントの移動』が行う。

この PR は、レビューに合格した後にこのプロジェクトでマージする。マージは ai-monitor#3307 のマージを待たない。
