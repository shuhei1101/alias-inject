# 要件

## 要望

共通のスキーマを、dev-docs.yaml の documents の行と同じ構造の「エイリアスの元の行」に変え、alias-inject は documents の行のうち `metadata.alias_type` を持つ行を照合の定義として読む（D-164・D-165・D-167。整理は A-25・A-26・A-36）。

- 行は `id`・`paths[]`・`records`・`metadata` を持つ。dev-docs・mdmark の行が持つ他のキー（`type`・`schema` 等）と、`metadata` の共通のキー（`tags`・`status` 等）は検証で弾かない
- `paths[]` に当たった各ファイルが 1 件の文書になる。`records` を書いた行は、ファイルの中のその配列の各要素を 1 件の文書にする
- `metadata` の各キーの値は `{type: ref, field: 列名}`（文書の列から取る）か `{type: custom, value: 値}`（行の全文書に同じ値）。書かないキーは同じ名前の列の `ref` とみなす
- `metadata` に書けるエイリアスのキーは `alias_type`・`id`・`name`・`aliases`・`description`・`related`・`command`・`cwd`・`url`・`avoid`・`skill`・`tool`・`path`・`port`・`replacement`
- `alias_type` は term・doc・command・url・skill・tool・path・env・avoid の 9 つ。種類ごとの必須・任意のキーは #12 の定義を引き継ぐ（下の表）
- 照合する語は `name` と `aliases` の値。文脈に出す語は `name` の値
- `name` が空の文書は、ファイル名（拡張子を除く）を使い、`records` の要素は `id` を使う（D-166）
- 必須のキーの値が空の文書は照合から外し、理由を debug log に出す。`alias_type` の値が 9 つのどれでもない文書も同じ
- 端末の設定の端末だけのエイリアスも、同じ構造の行で書く
- 今の `aliases[]` の構造（`type`・`fields`）は読まない。dev-docs.yaml のトップレベルの `aliases` は読まず、設定ファイルの旧い構造の要素はスキーマに合わない要素として外す
- 端末の設定を旧い構造から移し替える手順を、公開ドキュメントに置く
- 追加する文脈の書式（セクションの見出し・並び・種類ごとの列）は変えない

<!-- table: data -->

| alias_type | 必須のキー | 任意のキー |
| --- | --- | --- |
| term | `id`・`name`・`description` | `aliases`・`related`・`avoid` |
| doc | `id`・`name`・`description` | `aliases` |
| command | `id`・`name`・`command` | `aliases`・`description`・`cwd` |
| url | `id`・`name`・`url` | `aliases`・`description` |
| skill | `id`・`name`・`skill` | `aliases`・`description` |
| tool | `id`・`name`・`tool` | `aliases`・`description` |
| path | `id`・`name`・`path` | `aliases`・`description` |
| env | `id`・`name` と、`url`・`port` の 1 つ以上 | `aliases`・`description` |
| avoid | `id`・`name`・`replacement` | `aliases` |

<!-- /table -->

`avoid` の種類（やめた言い方と `replacement` の組）は、term のキー `avoid`（用語ごとのやめた言い方）とは別に残す。

スキーマを含むリリースのタグは、Sprint の release を master へ入れるときに打つ。
mdmark・dev-docs はそのタグを指定して取り込む（D-120）。

端末の設定で行を並べるキーは、今の `aliases` のままにする（インターフェース定義設計で決定）。
A-26 が mdmark の設定の行の置き場所を `aliases` にしており、それに揃える。

スキーマのファイル名は `schemas/aliases.schema.yaml` のままにする（モジュール構成設計で決定）。
取り込む側（mdmark#125・dev-docs#11）が指すパスを変えずに済む。

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| mdmark・dev-docs がこのスキーマのタグを指定して取り込む | 取り込む側のリポジトリの作業で、この PR のスキーマとタグを前提にする。タグを打った後に、後続の Issue へ着手できることを連絡する（#8 で連絡を依頼した shuhei1101/dev-docs#3 にも連絡する） | shuhei1101/mdmark#125・shuhei1101/dev-docs#11 |
| 旧い `aliases[]` の構造の読み込みの互換 | Issue の要望で、旧い構造は読まない（破壊的変更）。移し替えの手順で代える | 予定なし |
| `records` を書かない、最上位が並びの YAML を項目の並びとして読む | `paths[]` の各ファイルを 1 件の文書にする dev-docs の documents の行と読み方を揃える。並びの YAML は移し替えの手順で `records` を持つ構造へ移す | 予定なし |
| `metadata` の共通のキー（`tags`・`status`）を照合・文脈に使う | 検索と画面のための dev-docs のキーで、引用の文脈には要らない | 予定なし |
| 設計書の検証が `dev/pr/21/反映作業/index.yaml` を目次の Schema（`dev/テンプレート/index.schema.yaml`）で検証し、`items`・`summary` の欠けと作業名を Schema に無い項目として返す | ファイルはテンプレート『PRドキュメント/反映作業』の書式どおりで、検証する側（ai-monitor）の不具合。今回の要望に含まれない | shuhei1101/ai-monitor#2704 |
