### 型の取り込み方

| 取り込み方 | 結果 |
| --- | --- |
| (1) 対話のセッションを `claude --plugin-dir {PoC の worktree}` で 1 度起動する | エンジンが `.claude-plugin/types/`（`claude-code`・`claude-code-tools`・`claude-code-mcp` の宣言と `tsconfig.json`）と、mod の直下の `tsconfig.json`（`.claude-plugin/types/tsconfig.json` を `extends` する 1 行）を書き出した。`tsc -p tsconfig.json` は終了コード 0 |
| (2) 型ファイルの先頭の `tsconfig.json` を mod のフォルダの外に置く | plugin-authoring のスキルを読み込んだときに書き出される `claude-code.d.ts` と `hooks/` を `include` に並べ、終了コード 0 |

- 採る取り込み方: (1)
  - 直下の `tsconfig.json` を書き出すのはエンジンで、手で書く設定が要らない
- git 管理: 直下の `tsconfig.json` は入れ、`.claude-plugin/types/` は入れない
  - `.claude-plugin/types/` には、エンジンが中に `*` の `.gitignore` を置く
  - 宣言は Claude Code のバージョンごとに書き出し直される
- 対話のセッションを起動できない場所: 対話のセッションを起動しない限り `.claude-plugin/types/` は書き出されない
  - implementer などの自動のセッションは、tmux の中で信頼済みのフォルダから `claude --plugin-dir {worktree}` を 1 度起動して書き出してから `tsc` を流す
  - CI は今は持たない
- `claude plugin test` と `claude plugin validate` は型の宣言が無くても流せる

### 最小再現コードの要点

`hooks/hooks.json` は `{ "modules": ["./register.tsx"] }` の 1 行で、`register.tsx` を読む。

```tsx
export const register: Register = on => {
  on('prompt.submit', ($, e, next) =>
    next({ ...e, context: [...(e.context ?? []), `目印: ${POC_MARKER}`] }),
  )
}
```

テストはエンジンの代わりに届いた文脈を返すフックを置き、`$.prompt.submit` の結果の `context` を比べる。

```ts
on('prompt.submit', (_, e) => ({ text: e.text, context: e.context }))
const result = await $.prompt.submit({ text: 'hello', wait: false, origin: { kind: 'composer' } })
expect(result.context).toEqual(['目印: ALIAS-INJECT-POC-7f3a'])
```

PR #6 の diff の見どころ:

- `.claude-plugin/marketplace.json`: `plugins[0].source` が `./` で、リポジトリ自身を 1 つのプラグインとして載せる
  - フォルダから導入したプラグインは複製ではなく、そのフォルダから読まれる（`claude plugin list` の `Read from:`）
- `.claude-plugin/plugin.json`: version を置かない（`validate` は警告を出すが通る）
- `hooks/register.test.ts`: `$.prompt.submit` の引数は `wait` と `origin` が型の上で必須
