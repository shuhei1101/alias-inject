## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| プラグインの定義 | `.claude-plugin/plugin.json` に名前 `alias-inject`・説明・バージョンを書く | MCP サーバー（`.mcp.json`）は置かない |
| マーケットプレイスの定義 | `.claude-plugin/marketplace.json` にリポジトリ自身を 1 つのプラグインとして登録する | 利用者はユーザースコープで入れる |
| hooks モジュールの入口 | `hooks/hooks.json` の `modules` に `hooks/register.tsx` を登録し、`register.tsx` は処理を登録しない空の入口にする | `prompt.submit` などの処理は #1 が載せる。PoC 検証で読み込まれることを確かめる |
| 型の確認 | `tsconfig.json` を置き、`tsc -p` で `hooks/` の型を確かめる | mod の型定義の取り込み方は PoC 検証で確かめる |
| テスト | `claude plugin test` で流すテストを置き、空の入口を読み込んでもエラーにならないことを確かめる 1 件以上を pass させる | `claude plugin validate` も通す |
| 動作環境 | 利用者の手元の Claude Code（ターミナル版）で動かす | 常駐するサーバーは持たない |
| フォルダ構成 | rule-inject の単独のプラグインのプロジェクトにそろえる（`.claude-plugin/`・`hooks/`・`dev/`・`docs/`・`README.md`・`CLAUDE.md`） | rule-inject の MCP サーバーまわり（`.mcp.json`・Python のプロジェクト）は持ち込まない |
