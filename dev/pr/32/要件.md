# 要件

## 要望

文書を指す名前をエイリアスに登録するかを決める判定フローチャートを、公開ドキュメントの使い方に追加し、alias-inject の文書として dev-docs で配信する。

- 判定の軸は、話し合い（A-19・D-108）の案の 4 つを順に当てる
  1. 会話・Issue・本文で、実際にその名前で呼ばれたか
  2. 複数の文書や用語に当てはまる一般語か（例: 「設定」「手順」）
  3. 1〜2 文字の語か、ほかの語の一部としてよく出る語か
  4. 全角半角・大文字小文字の正規化で吸収できる表記ゆれか
- 終端は「登録する」と、判定ごとの「登録しない」にする
- 図はマーメイドの `flowchart TD` で描き、用語は図の直下に `※N` の定義を並べる
- リポジトリ直下に dev-docs の配信元の設定 `dev-docs.yaml` を新しく置き、このページを `documents[]` の行に載せてタグを付ける
  - 行は `metadata.alias_type` を持たせない（alias-inject の照合の対象にしない）
  - `dev-docs.yaml` は dev-docs のスキーマ（`src/dev_docs/schemas/dev-docs.schema.yaml`）に合うことを確かめる
- このページは rule-inject では注入しない（rules.yaml に登録しない。D-110）

`未確定`: ページに付けるタグ（決める段: ドキュメント修正）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | knowledge の語彙（`docs/tags.yaml`）の共通のグループに合う語を付け、合う語が無い主題は未登録の候補として付ける | D-104 のとおり、共通の分類が他のリポジトリと揃う | knowledge の語彙を確かめる手間が掛かる |
| B | alias-inject 固有の候補のタグだけを付ける | 語彙を確かめずに付けられる | 他のリポジトリの判定フローチャートと同じタグで引けない |

推奨: A

D-110 で他のリポジトリにも判定フローチャートを置くため、共通のグループのタグが揃っていればまとめて引ける。

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| knowledge の規約『タグと用語の登録』の条件の表を、このページを参照する形にする | knowledge のリポジトリの規約で、Issue 本文で knowledge 側の Issue が扱うと決めている | shuhei1101/knowledge#86 |
| alias-inject のタグのマスター（dev-docs.yaml の `tags`）を置く | dev-docs はタグのマスターのファイルの書式を決めておらず、語彙の置き方は D-104 の取り込みで各リポジトリが揃えて決める。規約『タグと用語の登録』は未登録の候補のタグを検索に使ってよいとしているため、このページはマスター無しでタグで引ける | 予定なし |
| 端末の設定（`~/.config/dev-docs/settings.yaml`）に alias-inject の配信元の行を追加し、手元で配信する | この端末には dev-docs の端末の設定が無く、dev-docs の導入そのものはこの Issue の範囲を超える。配信元の行は、この PR の `dev-docs.yaml` を前提にする | #33 |
| alias-inject のほかの文書（`docs/`・`dev/`）を dev-docs で配信する | Issue の範囲はこのページの配信だけで、既存の文書の配信は D-101 の各リポジトリの取り込みで扱う | #34 |
